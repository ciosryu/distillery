# 증류소 타이쿤 — 설계 정합성 감사 및 Claude Code 이관안

작성일: 2026-11-13, Asia/Tokyo. 상태: **근거 확인본 v0.1 / 확인된 요구사항은 작업 가능 / CORE 전체 동결은 미완료**.

**첫 이관 경계는 지금의 읽기 전용 현황 감사와 문서 정합화다. 코드 변경은 요구사항·입출력·완료 기준이 동결된 묶음부터 시작한다.** 기존 확정 기준에서 유료 Early Access의 목표는 자체 증류한 **15년 싱글 몰트 위스키**의 최초 정상 유상 판매까지 완주하는 Godot PC 게임이다. 원액의 숙성 기간과 캠페인 경과 기간을 구분한다.

**최신 검토안:** 사용자가 감사 도중 목표를 **12년 싱글 몰트 위스키의 출하**로 낮추는 방안을 제안했다. 이 감사의 권장은 **12년 싱글 몰트 위스키의 최초 유상 출하**로 조정하는 것이다. 질문 형태의 제안이므로 확정 결정으로 기록하지 않았다. 본문 180개월 수용 기준은 기존 확정안이며, 변경이 채택되면 목표 원액의 숙성 기준만 144개월로 바꾸고 계보·자가 몰트·정상 판매·참값 비공개 조건을 유지한다. 아래 §11 참조.

## 2. 통합 규칙과 식별자

- `LEGACY-001~270`: 기존 번호 보존. `CORE-001~109`: 대화의 별도 결정. `REPO-271~307`: 최신 저장소의 추가 결정. 같은 숫자가 같은 결정을 뜻하지 않는다.
- 저장소의 기존 #번호를 재발급하거나 바꾸지 않는다. CORE는 외부 결정의 별칭이며 PM의 다음 정식 번호 #308을 대신하지 않는다.
- 우선순위: **이번 사용자 요구 → 확인한 최신 오너 확정 의도 → 해당 항목의 최신 저장소 결정 → 기존 기준 → 제안·실험 기록**. 단순히 숫자가 크거나 코드가 존재한다는 이유로 우선하지 않는다.
- KEEP = 충돌 없는 규칙 유지. OVERRIDE = 충돌한 조항만 교체. EXTEND = 기존 기반에 새 계약 추가. DEFER = 기능을 특정 출시 단계로 이관. 하나의 결정에 여러 절이 있으면 절별로 분리한다.
- `EVIDENCE_PENDING`은 자료 상태다. DEFER라는 기능 범위 결정과 다르다. 확인되지 않은 관계의 disposition은 null로 둔다.
- 설계 상태와 구현 상태는 별도 열로 관리한다. 구현은 Implemented / Partial / Missing / Conflict, 검증은 Executed / Static-only / Not-run으로 구분한다.
- 역사 기록은 덮어쓰지 않는다. 현재 사양 문서의 충돌 조항을 고치고, 옛 결정에는 후속 대응 링크를 단다. P0 해소 전에는 전체 통합 완료를 표시하지 않는다.

## 6. MVP / Early Access / 1.0 범위

MVP는 내부 기능·재미 검증용 웹 빌드다. Early Access는 그 기능을 완주 가능한 유료 제품으로 제공하는 출시 관문이다. EA라는 이유로 승리·저장·재무 위기를 나중에 완성하지 않는다. 이 범위표는 확보된 최신 대화의 범위를 적용했고 세부 원문 미확인 항목은 전체 동결 대상에서 제외한다.

| 영역 | MVP 기능 기준 | 유료 EA 출시 관문 | 1.0 확장 |
|---|---|---|---|
| 캠페인 | 한국의 단일 증류소 자유 창업, 목표 판매까지 전체 루프, 180개월 후 지속 | 자체 증류한 15년 싱글 몰트 위스키의 판매·승리·패배·이후 계속하기 검증 | 다수 스토리 캠페인·시작 조건 확장 |

기존 MVP 기능을 초기부터 모두 동시에 개방한다는 뜻은 아니다. 생산·경영 인과를 해치지 않는 순차 안내를 둔다. 수출을 빼는 대신 기존 수출 목표를 국내 출시·브랜드·적격 원액 준비 목표로 치환한다. 상세 HR을 잠가도 기본 영업·증류 역량을 0으로 만들지 않는다.

## 7. 기술 아키텍처 영향과 구현 의존성

**기존 엔진을 유지하면서 데이터 계약을 먼저 보강한다.** 저장소 전체 재작성이나 Godot 선행 이식은 이번 최소 패치의 범위가 아니다.

| 계약/상태 | 필요한 보강(설계안, 아직 코드 아님) | 의존·주의 |
|---|---|---|
| RuleSet / GameSetup | scenarioId·규칙/콘텐츠/설정 버전·시드·모드 여부·6영역 난이도 스냅샷 | 새 게임과 세이브 호환 정책의 출발점 |
| Batch / ComponentLedger | batchId·증류소 출처·자가/매입/미상·공정/원료 자격·기여 LPA·누적 적격 목재 숙성·분할/혼합 부모 | 통입·이동·혼합·병입·보충·출고 모두 계보 보존. createdMonth 하나로 숙성 계산 금지 |
| Observation / PlayerView | 관측 시점·방법·추정치·불확실성·비용. 엔진 참값은 분리 | UI·추천·자동화·공개 평가액이 이 경계만 읽음. 실제 세계 수요/생산 결과는 참상태 사용 가능 |
| BottledLot / SaleEvent | 제품 SKU와 병입 로트 분리, 실제 출고 로트 할당·가격·수량·거래 확정·당시 적격성 | 과거 totalSold + 현재 혼합 품질/나이로 승리 추정 금지 |
| CampaignProgress | 적격 판매 사건·승리월·거래 ID·성과지표를 별도 보관 | 순자산은 성과, 승리 자격을 대체하지 못함. 승리 한 번·180개월 이후 지속 |
| Valuation / Rights | 장부 원가·관측 기반 시장 추정·처분비용/시간 반영 예상액·소유/담보/선판매 의무 | 샘플 결과 변화로 추정 평가액만 바뀔 수 있음. 관측만으로 현금·장부 손익을 만들지 않음 |
| RNG / replay | 기존 rngFor와 대상별 키 유지, 새 변동에만 버전 달린 스트림 명세 | C#에서 해시·부호없는 연산·정렬·정규분포·월 순서 동일. Math.random/시각 의존 금지 |
| Migration | 의미가 바뀌는 신규 버전, 미상 출처 명시·원본 보존·구규칙 판 분리 | 존재하지 않는 과거 배치·유상 판매 증거를 창작하지 않음 |

의존 순서:

```text
근거·결정 원장 → 범위·규칙 ID 동결 → 저장/호환 계약
                                ↓
                         배치·출처·분할·혼합
                                ↓
               병입 로트·정상 판매 사건 → 캠페인 승리
                                ↓
관측/PlayerView → 공개 가치평가 → 담보/선판매 → 추천·정책 자동화
                                ↓
                6영역 난이도·새 캠페인 해금·핵심 인력
                                ↓
           통합 회귀·완주 → 새 봇·밸런스 → 후반 경험 게이트 L
                                ↓
                  TS 동결·골든 → Godot/C# → 유료 EA
```

관측 경계와 배치 계약은 서로 독립된 명세 초안을 준비할 수 있지만, 같은 코어 타입·저장 구조를 동시에 무조정 변경하지 않는다. 승리의 핵심 조건과 출처는 한 묶음의 통합 테스트에서 검증한다. 난이도를 먼저 수치 튜닝하면 아직 바뀔 경제를 두 번 맞추게 된다.

각 PR은 한 주제·작은 코어 변경으로 나눈다. 기존 테스트가 구규칙을 검증하면 삭제로 통과시키지 말고 구규칙 호환 테스트와 새 규칙 테스트를 분리한다. 규칙 교체 PR의 수치 출력 변화는 예상 변화로 명시하고, 무관한 시나리오의 골든은 유지한다. 저장소 외부로의 머지·푸시를 이번 문서 작성 작업에서 수행하지 않았다.

붙여 넣을 지시문은 [단계별 Claude Code 프롬프트](claude-code-prompts.md)에 있다. 첫 프롬프트부터 진행하면 되며 설계 질문을 다시 열 필요가 없다. 원문이 없는 기능은 근거 복원 목록에 남기고 독립된 확정 묶음의 작업을 계속한다.

## 9. 새 검증·밸런스 규격

### 기능 관문

1. 자가 몰트 180개월·정상 유상 판매 통과. 179개월·미판매·무료·선수금만·그레인·매입·출처미상·최소 연수 미달 혼합은 실패. 동일 적격 거래는 승리 한 번.
2. 탱크·비목재 휴지·병 보관은 목표 목재 숙성에 가산하지 않는다. 피니싱 이동은 적격 목재 기간의 실제 합만 보존한다. 가장 어린 구성 원액을 기준으로 한다.
3. 배치 분할/혼합/병입/제품 보충/판매에서 출처 비율·잔량·원가가 보존된다. 샘플·증발·누수는 손실 사건으로 정산한다.
4. 동일 공개 정보에서 숨은 품질을 바꿔도 UI·자동화·재무 추정·가격 제안은 동일하다. 실제 시장 결과는 참품질 영향 허용. 판매로 얻은 신호는 새 관측으로 다루고 정답 숫자를 공개하지 않는다.
5. 정상 저장·재시작·구버전 이전·오염 저장 수리·원본 보존 검증. 같은 설정·시드·명령 재실행 및 재개 결과 동일.
6. 새 게임의 수출·상세 HR은 끝까지 잠김, 핵심 인력·국내 시장·실험제품·그레인/기본 블렌드 경로는 사용 가능. 난이도는 숙성·출처·정보 비대칭의 기본 규칙을 제거하지 않는다.

### 밸런스 관문

- **기존 180개월 성공률·micro 70~90% / standard 40~60%는 구순자산 목표에 대한 잠정 수치**다. 새 판매 승리의 확정 합격선으로 재사용하지 않는다. 목표 달성·생존·성과등급을 따로 기록한다.
- 공식 3프리셋 × 각 개방 규모 × 고정 40시드에서, 사전 고정한 합리 전략군을 비교한다. 전략군에는 국내 현금흐름형·몰트 보유형·혼합형·단일 SKU·관광 유무·차입 유무·수동/정책 가격 대조를 포함한다. 숨은 상태를 읽는 봇은 판정에서 제외한다.
- 신규 관측 기간은 우선 240개월, 360개월 민감도 확인을 감사 권장 측정 규약으로 둔다. **이는 게임 종료 시점이 아니다.** 측정 끝까지 미완주면 관측 종료(censored), 파산·구매/출고 실패와 구분한다. 안정화된 승리 시점 분포를 보고 측정 기간을 조정한다.
- 시드별 최초 적격 판매월·숙성 시작 지연·현금 최저·3개월 위기·누적차입·순자산 3종·적격 원액 잔량·소모 원인·병입창·샘플 비용/정보 가치·가격/공급 정책 변경·8년 이후 의미 있는 선택을 기록한다.
- 기존 **단일 전략 1위 60% 이하**는 참고 기준을 보존하되, 비교 전략·순위 기준·시점·미완주/파산 처리를 먼저 고정한다. 승리 속도와 경제 성과를 섞어 하나의 임의 점수로 만들지 않는다.
- 보유 전략은 REPO-306에 따라 그 전략에 맞는 가격 정책에서도 비교한다. A를 선택한 사람의 장기 보유 손해·B/C 전환 이해 여부도 후반 경험 검증에 포함한다.
- Custom은 3^6=729조합 모두의 동일 승률을 요구하지 않는다. 설정 직렬화·허용 조합은 전수 확인하고, 전영역 Easy/Normal/Hard·각 영역 단독 Hard·거시/금융/공급망 복합 충격·다중 극단 조합은 재현 가능한 표로 검사한다.
- 40시드 결과에 원자료·Wilson 구간·시드 짝 차이·전략 분포를 제공한다. 현재 수치가 통과했다고 주장하지 않는다. 새 성공률의 수치 합격선은 새 지표의 근거를 확보한 뒤 위임 범위에서 문서화한다.
- 게이트 L을 유지하되 8~15년에서 목표 판매 완료 이후까지로 관측을 확장한다. 장기 대기 중 의미 있는 선택과 자동 진행/개입의 균형을 사람 판에서 확인한다.

## 11. 최신 검토 — 목표를 12년 유상 출하로 변경

36개월은 숙성 대기의 차이다. 실제 플레이 시간이나 개발 공수가 같은 비율로 줄어든다는 측정 결과는 없다. 12년으로 낮춰도 기존 코드가 그대로 정답이 되지는 않는다. 현재 구현은 매입·그레인/블렌드 자격을 배제하지 않으며, 순자산만의 달성·180개월 고정 판정·누적 totalSold 소급 인정 위험을 그대로 갖는다.

채택 시 문서 변경 범위:

- 목표 요구를 한 파라미터 `campaignGoal.minOakMonths`로 관리하고 값은 144. 테스트의 179/180 경계는 143/144로 교체한다.
