1. **임금 상승률 하나로는 옛 비용의 모양을 맞출 수 없다.**

   - `wageDrift`는 1년 차부터 복리로 쌓인다. 그래서 240개월 비용을 맞추는 값(≈1.015)은 180개월 비용이 옛 것의 2.3~2.6배다. 180개월을 맞추는 값은 1.01보다 작다(보간 ≈1.005 `[추정 — 재지 않음]`).

2. **`wageDrift`는 Death Valley를 거의 건드리지 않는다. `laborMul`은 건드린다.**

## [제안 P-MGT-54] Normal 값
- **`finance.wageDrift` Normal = 연 +1% (`w = 1.01`). `finance.laborMul` Normal = 1(지금 그대로).**
  - 근거 1: 캠페인 지평(180)에서 X0 비용 2.2억(순자산의 6~8%)으로 옛 비용의 1.7~1.9배다. 1.015(2.3~2.6배)보다 옛 손맛에 가깝다. 240에서는 옛 비용의 70~76%다.
  - 근거 2: X0 std 180 목표 달성 80%는 1.015와 같고 1.02(50%)보다 안전하다.
  - 근거 3: Death Valley·파산·승리를 바꾸지 않는다. Normal의 초반 난이도는 그대로 두고 후반 압력만 더한다.
  - 근거 4: `laborMul`을 Normal에서 올리면 초반 생존(최저 현금 −45%, micro)을 건드린다. F6에서 Hard 금융의 몫으로 정한 성격과 겹친다.
- **대안 A — 1.015:** PM이 대조로 제시한 「+5.24억 @ std 240」을 그대로 맞춘다(104~112%). 대신 15년 캠페인 안에서는 옛 판보다 2.3~2.6배 무겁다.
- **대안 B — Normal 1(오르지 않음), Hard에만 상승률:** v16 Normal이 옛 판보다 구조적으로 1.2억(15년) 쉽다는 점을 받아들이는 선택이다.

## [의견] Normal 값을 어디에 둘 것인가 — (a) `KnobDef.normal?` · (b) 기본 규칙 상수 × 배수 · (c) 기타
- **MGT 의견: (b).** v16 규칙 묶음에 기본 상승률 상수 `baseWageDrift = 0.01`을 둔다. `rulesVersion` 'v16'일 때만 쓰고, legacy는 0이다.
  - 실효 상승률 = 1 + `baseWageDrift` × `knob(s,'finance.wageDrift')`
  - 손잡이는 지금처럼 Normal = ×1이다. Easy ×0이면 오르지 않고, Hard ×2~3이면 2~3%다.
  - 이유 ① `knob(s,id)`가 Normal에서 늘 1이라는 규약이 그대로다. `mgtKnobs.ts`의 `mul` 빠른 길, F6 정적 테스트(#567), "Normal = 지금 값" 문서도 그대로다. (a)는 이 규약에 예외를 하나 만든다.
  - 이유 ② Normal 값이 판본마다 달라야 한다(legacy는 0이라야 X0L이 바이트 동일). (a)는 `KnobDef.normal`을 판본별로 또 나눠야 한다. (b)는 판본 묶음 상수라 이미 나뉜 자리다.
  - 이유 ③ 다른 손잡이(금리·한도·피해 크기)도 모두 "기본값 × 배수"다. `wageDrift`만 "값 그 자체"인 지금 형태가 예외다. (b)로 바꾸면 통일된다.
- **(b)의 비용과 리스크:**
  - `finance.wageDrift`의 뜻이 「연 배수 값」에서 「기본 상승률에 곱하는 배수」로 바뀐다. `difficulty.ts` 주석, `mgtKnobs.ts`·`mgtKnobs.test.ts`(Hard 1.05 시험), architecture §10.10 문구를 같은 PR에서 고친다. 코어(`rules.ts` 판본 묶음)라서 작은 코어 PR이다(ARCH 또는 코어 대행).
  - 진행 중인 v16 세이브는 다음 1월부터 오르기 시작한다. 단계 P라 세이브 호환 이슈로 보지 않지만, 플레이테스트용 세이브를 만들기 전에 넣는 것이 깔끔하다.
- **(c) 변형:** 상수를 판본 묶음이 아니라 시나리오 콘텐츠(`mvp_kr`의 캠페인 규칙)에 둔다. 시나리오마다 다른 임금 압력(지역 인건비 상승률)을 줄 수 있지만, 지금은 시나리오가 하나라 이득이 없다 → (b)를 먼저 하고 필요하면 (c)로 옮긴다.

### 읽기
1. **3단 간격이 고르다.** std 180에서 Easy ↔ Normal ↔ Hard가 각각 4.8억(순자산의 약 17%)씩 벌어진다.
   - Hard 비용(7.03억)은 따로 잰 1.02(4.15)와 ×1.1(2.79)의 합 6.94와 거의 같다. 두 손잡이는 대체로 더해진다 `[관측, 10시드]`.
2. **Hard에서 움직이는 판정 지표는 standard X0의 순자산 목표(30%)뿐이다.** 파산·승리·승리 달은 그대로다.
   - Hard 임금이 「질 수 있는 판」을 만드는 경로는 목표 미달이지 파산이 아니다.
   - Death Valley는 micro 최저 현금이 0.33억(X12F 0.24억)까지 내려가 가장 얇아진다.
3. **Hard는 standard 대출 한도(5억)에 닿는다.** X0 최대 대출 잔액이 3.0 → 5.0억이다.
   - Hard의 다른 금융 손잡이(`loanLimit`·`loanRate`, 지금 값 1)를 키우면 이 판은 한도에서 막힌다. 그러면 파산이 처음 나올 수 있다 `[추론]`.
   - 그래서 Hard 금융 크기는 임금 손잡이와 **한 판에서 함께** 재야 한다(F7 `[튜닝]`).
4. **Easy `laborMul` 0.9는 Death Valley 최저 현금을 거의 올리지 않는다**(std 0.62 → 0.61).
   - 최저 현금은 봇의 설비·통 구매 시점(12~24개월)이 정한다. 급여 10%는 그보다 작다.
   - 위기 개월은 9.7 → 2.5로 크게 준다. Easy가 체감되는 곳은 「바닥 깊이」가 아니라 「바닥에 머무는 기간」이다.
5. 위기 개월이 Hard(7.7) < Normal(14.0)로 거꾸로 나온다. Hard 판이 대출을 더 써서(5억) 현금 완충이 커지기 때문이다 `[추론]`. 위기 개월만으로 난이도를 읽으면 안 된다.

### 반론
- **Hard에서 standard 목표 달성 30%는 봇 기준이다.** 봇은 Hard에서도 같은 행동을 한다(가격·채용 대응 없음). 사람은 대응하므로 실제 체감은 이보다 덜 어려울 것이다 `[추측]`.
- micro는 Hard에서도 목표 100%다. 「Hard = micro에서도 압력」을 원하면 임금만으로는 부족하다. 다른 영역 손잡이와 합친 판에서 다시 본다.

## 반론·한계
- **10시드.** 1.01과 1.015 사이, 1.01과 laborMul 1.1 사이의 순위는 신뢰구간 안이다. 비용 차이 1억 미만은 읽지 않는다.
- 봇 X0·X12F만 쟀다. 핵심 전문가 효과(영업)가 들어 있고, 사람은 직원 구성이 다를 수 있다.
- 비용은 순자산 평균 차이다. 경로 효과(대출·가격)가 섞여 있어 "급여 증가분 합계"와 같지 않다.
- 옛 비용 대조는 옛 v16(수출 열림·HR 해금) 판이라 새 X0와 경로가 다르다. 비교하는 것은 크기(억)뿐이다.
