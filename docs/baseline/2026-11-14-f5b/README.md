## 읽기 (MGT — 판정 아님)
1. **봇 `fill()`의 `contamination` → `contaminationKnown`은 지금 규칙에서 행동이 같다.** 근거(코드 읽기):
   - `maturation.ts emptyCask`는 통을 비울 때 오염을 드러낸다(`contaminationKnown: true`).
   - 오염은 원액이 든 통에만 생긴다(`warehouse.ts runContamination`은 빈 통을 건너뛰고, `events.ts`도 찬 통에서 고른다).
   - 그래서 **빈 통에서는 "오염 ⇒ 앎"이 늘 참**이다. 통입 대상은 빈 통뿐이라 두 조건이 같다. 숨은 오염 통 통입 0.0(전 칸)이 그 실측이다.
   - 함의: #534의 `autoFill`·`fillCasks` 변경도 같은 이유로 지금은 행동 불변일 것이다 `[추론]`. 정보 누수는 이론상의 것이었다. 빈 통에 오염이 생기는 규칙(예: 빈 통 보관 곰팡이)이 생기면 그때 갈린다 — 그 규칙을 만들 때 이 불변식을 같이 볼 것.
2. **이 봇에서 순자산 정의 변경의 크기는 작다(−0.03 ~ −0.05억, 0.1~0.2%).** 판 끝에 통 원액이 적고(담보 가치 1.0 ~ 1.2억) 현금이 대부분이기 때문이다. 옛 식과 ③의 차이는 q̂ 사전값(45)과 병 재고 처분 계수가 만든다. **통을 많이 들고 끝나는 판**(증산 X12·X13, 장기 보유 `protectFrom`, 오너십 판매 전 등)에서는 차이가 커질 것이다 → F7에서 그 행들로 잰다 `[추론]`.
3. **담보 q̂ 대 참 품질: q̂가 1~4% 낮다.** 사전값 P25(45)라 맛보지 않은 통이 보수적으로 잡힌다. 한도에 닿는 것은 홋카이도 입지(`inventoryLtv` 0.6)뿐이다. P8은 경기 기본 입지라 이 값은 대출 한도에 쓰이지 않는다. 홋카이도 판정이 필요하면 따로 잰다.
4. **CALIB:** H1·H3(사람 판 21.14억 · 연말 계단)은 이제 `netWorthLegacy`로 비교한다(사람 판이 옛 식으로 잰 값). 옛 판 CALIB 출력은 바이트 동일.
