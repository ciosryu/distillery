## 인수인계 메모 (공정관리 세션 → 새 공정관리 세션, 2026-11-06)

- **머지 방식:** 작업 세션의 PR을 직접 머지하지 않고, PM 브랜치에서 `main` 위에 머지 커밋으로 합친 뒤 임시 ID → 정식 번호 커밋을 더해 PM PR 하나로 `main`에 머지한다. 원래 PR은 head가 `main`에 들어가 자동으로 "merged" 처리된다. 작업 세션 브랜치에는 커밋하지 않는다
- **머지 전 확인:** typecheck·test·build + "동작 불변"을 주장하는 PR은 `DIAG=1 npm run balance -- 2 120 all <닿는 지역>`과 `MVP=micro npx tsx scripts/experiments/mvp-survival.ts 2 180` 출력을 머지 전 `main`과 `cmp`로 비교한다. 지금까지 모두 바이트 동일이었다
- **번호 발급:** 오너가 "PR #N 머지"라고 하면 그 PR의 `[제안 P-…]`도 승인으로 기록해 왔다(오너가 이 해석을 문제 삼은 적 없음). 결정 표·재발급 이력·CLAUDE.md·PROCESS.md·STATUS.md의 번호를 함께 올린다
- **주의:** 작업 세션이 머지 순서를 지정하면 그 순서로 합친다. 쌓인 PR(다른 PR 위)은 앞 PR을 먼저 합친다. PR 알림은 오너가 채팅으로 알려 주는 방식(정기 확인 없음). 옛 PM 세션은 #5·#9 구독을 해제했다(2026-11-06) — 필요하면 새 PM 세션이 구독한다
- **열린 질문:** 아래 "오너 결정 대기" 2·3·6·9
