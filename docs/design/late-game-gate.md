## 3. 데이터 원천

1. **행동 기록 — 지금 있는 것:** `Playlog`(턴별 활동 시간·행동 수·빌드·되돌리기). **없는 것:** 어떤 행동인지 → `[제안 P-ARCH-44]` 플레이 기록에 **행동 타입 열**(달·행동 `type`·대상 수 — 인자 전체가 아니라 요약)을 선택 기능으로 더한다. 결정론 계약(architecture.md §9.4 "명령 기록")과 같은 기능이다. 세이브(`GameState`)가 아니라 플레이 기록에 둔다
2. **봇 반사실:** 사람 판·봇 판의 **8년 차(96개월) 세이브**에서, 같은 시드로 정책 묶음을 바꿔 180개월까지 돌린다(`mvp-human.ts` DUMP 방식 — 세이브에서 이어 돌리는 모드를 더한다). L1·L4가 쓴다. 정책 목록은 BAL이 판정 전에 고정한다(#278과 같은 원칙)
3. **결산·기록 파일:** `playtest-years.ts`·`playlog-report.ts` — 연도별 매출 구성·해금 사용·통 보유·자동 기능
4. **외부 플레이테스트:** 처음 하는 사람. 진행 중 생각 말하기(선택) + 사후 설문 + 짧은 면담
5. **"고를 것" 수:** 매달 소식 창의 선택 이벤트·할 일 목록 수(이미 화면에 있다 — 기록만 더한다). L3에서 "행동 0인 달"을 "고를 것도 없었다"와 "고를 것이 있었는데 넘겼다"로 나눈다

## 5. 합격 기준 `[제안 — 오너 승인 필요]`

> 수치는 **제안**이다. 근거가 얇은 칸은 그렇다고 적었다. 승인 전에는 판정에 쓰지 않는다.

| # | 합격 | 근거·성격 |
|---|---|---|
| L1 | 8년 차 세이브에서 정책 묶음 중 **서로 다른 3가지 이상**이 15년 결과를 의미 있게 가른다 — 순자산 차 ≥ 목표의 10% 또는 등급이 갈림(10시드 중앙값) | 봇. "10%"는 판정 보류 구간(BALANCE-SPEC)과 같이 정한다 `[근거 얇음]` |
| L2 | 외부 테스터 과반이 8년 차 뒤 해금 3종(수출 · IB/VIP · 직원) 중 **2종 이상**을 결과를 바꾸는 방식으로 쓴다(예: 시장 진입·입찰 수락/거절의 이유를 말함·채용) | 사람. 한 종도 안 쓰면 그 시스템은 정보·동기 문제(MKT·MGT) |
| L3 | 8~15년 중 **"고를 것이 있었는데 행동 0"인 달**이 연속 12개월을 넘는 테스터가 과반이 아니고, 사후 설문 "후반이 지루했다"(1~5)의 중앙값 ≤ 3 | 사람 + 기록. 행동 0인 달 자체는 실패가 아니다 |
| L4 | 8년 차 세이브에서 **적응 정책**(96개월에 생산·수출·숙성 보유 중 하나 이상 변경)이 **고정 정책**보다 시드 70% 이상에서 낫다 | 봇. 고정이 늘 이기면 후반에 바꿀 이유가 없다는 뜻 `[근거 얇음]` |
| L5 | 사후 설문의 기회비용 문항 5개(수출 대 국내 · IB 판매 대 플래그십 · 증산 대 현금 · 자동 가격 정책 · 예비 통) 정답률 중앙값 ≥ 70% | 사람. 문항은 게이트 전에 고정 |
| L6 | 외부 테스터 과반이 **골라서** 1통 이상을 플래그십용으로 남긴다(예비 태그·설명) — 그리고 PROD-A(#273) 측정에서 "일부만 장기 숙성"이 합리적인 상황이 있다 | 사람 + PROD-A |

- **게이트 결과:** 여섯 모두 통과 → 단계 G 착수(#274). 하나라도 실패 → 그 요소의 담당 파트가 원인을 진단하고, 규칙을 바꾸면 영향받은 단계 T 실험을 회귀(#274)
- 반론: 표본 6~8명으로 "과반"·"70%"는 흔들린다 → 그래서 L2·L3·L5·L6은 **면담 근거와 함께** 판정하고, 숫자만으로 통과·실패를 정하지 않는다. 숫자는 봇 기준(L1·L4)에 더 무게를 둔다
- 리스크: 게이트용으로 규칙을 바꾸면 경제 공식이 바뀔 수 있다 → #274 "영향받은 T 실험 회귀"를 실행 조건으로 적는다

## 6. 엣지 케이스 (최소 3)

1. **테스터가 8년 차 전에 그만둔다**(파산·흥미 상실·시간) — 후반 데이터가 없다. 그만둔 이유를 기록하고 표본에서 빼되, **그만둔 비율 자체**를 보고한다(초반 문제는 단계 T·MVP 기준의 몫). 그래서 표본 절반은 7년 차 세이브에서 시작한다
2. **모든 자동 기능을 켜고 잘 이긴다** — 실패가 아닐 수 있다(#275: 자동화는 반복을 맡는다). L3은 "고를 것이 있었는데 넘겼나"와 설문으로 본다. 자동화가 **판단까지** 대신했다면(예: 자동 가격이 포지셔닝을 정함) MKT-B 정책형 가격의 몫
3. **목표를 일찍 포기한 판**(플래그십 불가가 확정된 뒤) — 후반 확인 판이 그랬다. 동기가 사라진 판의 지루함과 구조의 지루함을 가른다: 면담에서 "목표가 남아 있었다면 무엇을 했겠나"를 묻고, 예비 통(#260)·후보 감소 알림(#261) 뒤의 판과 견준다
4. **7년 차 세이브 시작의 편향** — 앞 7년의 선택(설비·대출·통입)을 테스터가 하지 않았으니 후반 선택의 맥락을 모른다. 세이브에는 "지금까지의 요약"(연표·순자산 곡선·설비)을 보여 주고, 새 판 그룹과 결과를 따로 본다
5. **판 도중 빌드 변경** — #241 경고. 바뀐 판은 분석에서 표시하고 바뀐 뒤 구간만 쓴다
6. **봇 반사실의 정책 목록이 결과를 정한다**(#278과 같은 문제) — 목록을 BAL이 판정 전에 고정하고, 목록에 없는 사람의 정책은 사람 데이터로만 본다

### 9.3 `[COUNTER-PROPOSAL]` CP-ARCH-1 — 배너 넷 대신 "판단 카드" = 할 일 항목의 확장 (CP-PM-3 ⓑ 반박)

1. **기존 제안의 목적:** CP-PM-3 ⓑ — 선택이 경제에 있는데 안 보이면, 현금 위기 배너 패턴을 네 충돌로 넓혀 대안과 대가를 보인다
2. **문제점:** ① 배너는 모든 탭 맨 위 자리를 쓴다 — 넷이 겹치면 `CashBanner`·`SkipBanner`(진짜 위급)와 섞여 위급의 무게가 흐려진다(CP-PM-3도 엣지 ③으로 인정) ② 배너는 "지금 당장"의 문법인데 네 충돌 중 셋(국내 대 수출·현금 대 장기 자산·브랜드 방향)은 **몇 달 안에 정하면 되는** 판단이다 ③ 우선순위·순서 규칙이 할 일 목록(`TODO_ORDER`)과 별도로 하나 더 생긴다
3. **대안 설계:** 할 일 항목 타입에 선택 필드 **`options?`**(대안 2~3개: 이름·대가 한 줄·실행 = 기존 명령 또는 정책 값 설정)와 **`conflictKey`**(조건 서명 — 같은 충돌이 같은 상태로 다시 뜨지 않게)를 더한다. 화면은 지금 "이번 달 할 일" 안에서 카드로 펼친다(한 번에 최대 2장). **위급(파산·생산 건너뛰기)은 지금처럼 배너**, 판단은 카드 — 문법을 나눈다
   - 카드 발동은 **실제 상태 충돌만**(코드 조건이 이미 있는 것부터):
     | 충돌 | 발동 조건(지금 있는 계산) | 대안(기존 명령·정책) |
     |---|---|---|
     | 국내 대 수출 | `exportShortfalls`(#257) — 지난달 수출이 국내 재고를 먼저 가져감 | 그 제품 수출 안 함(#266) · 수출가 배수 올림 · 병입·증산(#272 전망 숫자) |
     | 숙성고 부족 | 자동 통입 "빈 통 모자람/자리 없음" 메모 또는 탱크 대기 원액 > 1개월 생산분 | 증설(설비 — 비용·완공 달) · 통 사기 · 생산 지시 줄이기(#272가 보이는 잃는 병 수) |
     | 현금 대 장기 자산 — **남는 쪽** | 현금 > 고정비 × k(예: 24개월)이고 대출 0 — `[튜닝]` | 증산(#272) · 숙성고 · 예비 통 늘리기(태그) · 그대로 둔다 |
     | 현금 대 장기 자산 — **모자란 쪽**(필수 엣지 4) | `cashAlert` + 예비 통 있음 | `CashBanner`에 한 줄 "예비 통 n개 — 풀면 약 y원(추정 범위)"(**배너 안**, 카드 아님 — 위급) |
     | 브랜드 방향 | 자동 가격이 정책 범위 끝에 n개월 붙음(가격 정책 B1 뒤) | 범위 바꾸기 · 그대로 |
   - **기본값 없음:** 카드를 닫으면 "지금 정책 유지"로 기록되고, `conflictKey`(조건 값의 구간 서명)가 바뀔 때까지 다시 뜨지 않는다. 고르지 않는 것이 행동을 만들지 않는다 — 이벤트 선택지의 "다음 달 기본값"과 다르다(엣지 9)
4. **재사용·호환:** `Todo` 타입(`alerts.ts`)·`TODO_ORDER`·`useGo` 이동·`ConfirmButton`(되돌릴 수 없는 대안)·정책 값(P-ARCH-40)·#272 전망·#257 계산. 닫은 서명은 **화면 상태**(브라우저 저장 — 시뮬레이션 결정론에 영향 없음), 선택 기록은 행동 기록(P-ARCH-44)으로. `GameState`는 정책 값 외에 바뀌지 않는다
5. **재미·밸런스 효과:** 판단이 필요한 달에만 대안과 대가가 보인다(L3). 경제를 바꾸지 않으므로 밸런스 이동 0 — **H1이면 효과도 0**(그래서 §10 반사실이 먼저)
6. **비용:** `Todo` 필드 2개 + 카드 렌더 1 + 조건 4개(셋은 이미 있다). CP-PM-3 배너 4개와 비슷하거나 작다 `[추론]` — 위급 배너의 자리 다툼이 없다
7. **새 악용·엣지:** ① 카드가 "정답"을 가리킨다 — 대안마다 대가를 **같은 형식**(원·병·개월)으로, 추천 표시 없음 ② 조건이 경계에서 깜빡임(현금이 24개월치를 오르내림) → 서명은 구간(예: 6개월 단위)으로 ③ 카드 대안이 정보 계약을 깨는 숫자(참 품질 가치)를 보임 → 추정값만(§11 architecture, CP-PM-5 ⓒ와 같은 규칙) ④ 할 일이 많은 달 카드가 밀림 → 카드는 할 일 목록 맨 위 두 칸(위급 배너 아래)
8. **검증:** 게이트 L — L3(고를 것이 있었는데 넘긴 달)·L2(해금 활용)·L5(기회비용 문항). 반사실(§10)로 카드 대안들이 실제로 결과를 가르는지(가르지 않는 대안은 카드에서 뺀다 — Q8)
9. **기존 안과 비교:** CP-PM-3 ⓐ(원인 분리 먼저)·ⓒ(경제 쪽이면 경제를 고친다)는 **그대로 동의**. 다른 것은 ⓑ의 그릇 — 배너 대신 할 일 카드, 위급만 배너. Agenda(⑤)보다 작고, CP-PM-3 ⓑ와 비용은 비슷하며 화면 충돌이 적다
10. **권고·신뢰도:** 권고 — 순서는 **① §10 반사실 도구로 H1/H2 판정(G03-MGT-1 결과 포함) → H2면 CP-ARCH-1, H1이면 B1 묶음·자본 배분 쪽**. 신뢰도 중(근거가 사람 판 하나와 #271 증산 반사실뿐)

### 9.4 엣지 케이스 (G03)

1. **H1·H2가 섞인다** — 어떤 충돌은 결과를 가르고(수출 배분) 어떤 것은 안 가른다(브랜드 방향). 카드는 반사실로 **가르는 것만** 둔다
2. **자동화가 충돌을 먼저 지운다** — 자동 가격이 범위를 따라가면 "브랜드 방향" 조건이 안 생긴다. 의도다(정책을 정했으니) — 카드는 정책이 **없을 때**와 정책이 **한계에 닿았을 때**만
3. **판 끝 근처**(170개월↑) — 몇 년 뒤에 효과가 나는 대안(증산·숙성고)은 판 안에서 회수되지 않는다 → #272의 "판 끝 약 e개월 전까지 늘려도 회수" 숫자를 카드에 그대로, 회수 불가면 그 대안을 숨긴다
4. **위급과 판단이 같은 달** — 배너(위급)가 먼저, 카드는 그 아래. 모자란 쪽 "현금 대 장기 자산"은 카드가 아니라 배너 안 한 줄(엣지 4)
