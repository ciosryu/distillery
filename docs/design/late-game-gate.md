# 후반 경험 게이트 L 설계 (ARCH-E, 2026-11-11) `[제안 P-ARCH-43]`

> 등급: **제안** — 검증 요소·데이터·표본·합격 기준 모두 **오너 승인 전**이다. 승인 뒤 정본.
> 근거: `[결정 #274]`(OWNER-2 — 후반(8~15년) 재미 검증은 단계 T 완료 뒤·단계 G 착수 전의 별도 필수 게이트, 설계는 ARCH-E 제안 뒤 오너 승인) · [requirements-audit.md](requirements-audit.md) §2.5 · 후반 확인 판 분석 [mvp.md](mvp.md) §7.21 · 문서 체계 `[결정 #279]`.
> 원칙: **클릭 수를 재미로 보지 않는다.** 행동이 적은 달이 나쁜 것이 아니라, "고를 것이 없어서" 적은 달이 나쁘다. 그래서 행동 기록은 **선택이 있었는지**를 보는 데 쓰고, 재미 판단은 사람의 응답과 봇의 반사실 실험을 함께 본다.

## 2. 검증 요소 (#274의 여섯 가지)

| # | 요소 | 무엇을 보면 "있다"고 하나 | 데이터 |
|---|---|---|---|
| L1 | **8~15년의 의미 있는 선택** | 8년 차 세이브에서 고를 수 있는 서로 다른 합리적 정책이 **결과를 다르게** 만든다(순자산·등급·플래그십) — 모든 길이 같은 곳에 닿으면 선택이 없다 | 봇 반사실(§3 ②) |
| L2 | **해금 시스템의 실제 활용** | 수출·IB 입찰·VIP·직원 관리를 사람이 **결과를 바꾸는 방식으로** 쓴다(켜 보기만 한 것은 제외) | 행동 기록(§3 ①) + 결산 + 면담 |
| L3 | **자동 진행과 개입의 균형** | 자동화가 반복을 맡고, 사람은 **판단이 필요한 달**에 개입한다. "할 일이 없어 넘긴 달"이 길게 이어지지 않는다 | 행동 기록 + 매달 "고를 것" 수(소식 창·할 일) + 면담 |
| L4 | **후반 전략 변경의 필요성** | 3년 차의 최선 정책을 15년까지 그대로 두는 것보다, 8년 차 전후에 바꾸는 것이 낫다(수출 배분·생산 규모·숙성 보유) | 봇 반사실(고정 대 적응) + 사람의 정책 변경 기록 |
| L5 | **기회비용 이해** | 사람이 후반 선택의 대가를 말할 수 있다(예: "IB에 팔면 플래그십 후보가 준다", "수출을 늘리면 국내 품절") | 사후 설문(정답 문항) |
| L6 | **장기 숙성 판단의 역할** | 일부 통을 **골라서** 오래 두는 판단이 결과에 기여하고, 사람이 그 판단을 한다(예비 통 #260·샘플 #273) | 결산(6년↑ 보유 통·플래그십) + 행동 기록(태그·샘플) + PROD-A(#273) 결과 |

## 3. 데이터 원천

1. **행동 기록 — 지금 있는 것:** `Playlog`(턴별 활동 시간·행동 수·빌드·되돌리기). **없는 것:** 어떤 행동인지 → `[제안 P-ARCH-44]` 플레이 기록에 **행동 타입 열**(달·행동 `type`·대상 수 — 인자 전체가 아니라 요약)을 선택 기능으로 더한다. 결정론 계약(architecture.md §9.4 "명령 기록")과 같은 기능이다. 세이브(`GameState`)가 아니라 플레이 기록에 둔다
2. **봇 반사실:** 사람 판·봇 판의 **8년 차(96개월) 세이브**에서, 같은 시드로 정책 묶음을 바꿔 180개월까지 돌린다(`mvp-human.ts` DUMP 방식 — 세이브에서 이어 돌리는 모드를 더한다). L1·L4가 쓴다. 정책 목록은 BAL이 판정 전에 고정한다(#278과 같은 원칙)
3. **결산·기록 파일:** `playtest-years.ts`·`playlog-report.ts` — 연도별 매출 구성·해금 사용·통 보유·자동 기능
4. **외부 플레이테스트:** 처음 하는 사람. 진행 중 생각 말하기(선택) + 사후 설문 + 짧은 면담
5. **"고를 것" 수:** 매달 소식 창의 선택 이벤트·할 일 목록 수(이미 화면에 있다 — 기록만 더한다). L3에서 "행동 0인 달"을 "고를 것도 없었다"와 "고를 것이 있었는데 넘겼다"로 나눈다

## 5. 합격 기준 `[제안 — 오너 승인 필요]`

> 수치는 **제안**이다. 근거가 얇은 칸은 그렇다고 적었다. 승인 전에는 판정에 쓰지 않는다.

| # | 합격 | 근거·성격 |
|---|---|---|
| L1 | 8년 차 세이브에서 정책 묶음 중 **서로 다른 3가지 이상**이 15년 결과를 의미 있게 가른다 — 순자산 차 ≥ 목표의 10% 또는 등급이 갈림(10시드 중앙값) | 봇. "10%"는 판정 보류 구간(BALANCE-SPEC)과 같이 정한다 `[근거 얇음]` |
| L2 | 외부 테스터 과반이 8년 차 뒤 해금 3종(수출 · IB/VIP · 직원) 중 **2종 이상**을 결과를 바꾸는 방식으로 쓴다(예: 시장 진입·입찰 수락/거절의 이유를 말함·채용) | 사람. 한 종도 안 쓰면 그 시스템은 정보·동기 문제(MKT·MGT) |
| L3 | 8~15년 중 **"고를 것이 있었는데 행동 0"인 달**이 연속 12개월을 넘는 테스터가 과반이 아니고, 사후 설문 "후반이 지루했다"(1~5)의 중앙값 ≤ 3 | 사람 + 기록. 행동 0인 달 자체는 실패가 아니다 |
| L4 | 8년 차 세이브에서 **적응 정책**(96개월에 생산·수출·숙성 보유 중 하나 이상 변경)이 **고정 정책**보다 시드 70% 이상에서 낫다 | 봇. 고정이 늘 이기면 후반에 바꿀 이유가 없다는 뜻 `[근거 얇음]` |
| L5 | 사후 설문의 기회비용 문항 5개(수출 대 국내 · IB 판매 대 플래그십 · 증산 대 현금 · 자동 가격 정책 · 예비 통) 정답률 중앙값 ≥ 70% | 사람. 문항은 게이트 전에 고정 |
| L6 | 외부 테스터 과반이 **골라서** 1통 이상을 플래그십용으로 남긴다(예비 태그·설명) — 그리고 PROD-A(#273) 측정에서 "일부만 장기 숙성"이 합리적인 상황이 있다 | 사람 + PROD-A |

- **게이트 결과:** 여섯 모두 통과 → 단계 G 착수(#274). 하나라도 실패 → 그 요소의 담당 파트가 원인을 진단하고, 규칙을 바꾸면 영향받은 단계 T 실험을 회귀(#274)
- 반론: 표본 6~8명으로 "과반"·"70%"는 흔들린다 → 그래서 L2·L3·L5·L6은 **면담 근거와 함께** 판정하고, 숫자만으로 통과·실패를 정하지 않는다. 숫자는 봇 기준(L1·L4)에 더 무게를 둔다
- 리스크: 게이트용으로 규칙을 바꾸면 경제 공식이 바뀔 수 있다 → #274 "영향받은 T 실험 회귀"를 실행 조건으로 적는다

## 6. 엣지 케이스 (최소 3)

1. **테스터가 8년 차 전에 그만둔다**(파산·흥미 상실·시간) — 후반 데이터가 없다. 그만둔 이유를 기록하고 표본에서 빼되, **그만둔 비율 자체**를 보고한다(초반 문제는 단계 T·MVP 기준의 몫). 그래서 표본 절반은 7년 차 세이브에서 시작한다
2. **모든 자동 기능을 켜고 잘 이긴다** — 실패가 아닐 수 있다(#275: 자동화는 반복을 맡는다). L3은 "고를 것이 있었는데 넘겼나"와 설문으로 본다. 자동화가 **판단까지** 대신했다면(예: 자동 가격이 포지셔닝을 정함) MKT-B 정책형 가격의 몫
3. **목표를 일찍 포기한 판**(플래그십 불가가 확정된 뒤) — 후반 확인 판이 그랬다. 동기가 사라진 판의 지루함과 구조의 지루함을 가른다: 면담에서 "목표가 남아 있었다면 무엇을 했겠나"를 묻고, 예비 통(#260)·후보 감소 알림(#261) 뒤의 판과 견준다
4. **7년 차 세이브 시작의 편향** — 앞 7년의 선택(설비·대출·통입)을 테스터가 하지 않았으니 후반 선택의 맥락을 모른다. 세이브에는 "지금까지의 요약"(연표·순자산 곡선·설비)을 보여 주고, 새 판 그룹과 결과를 따로 본다
5. **판 도중 빌드 변경** — #241 경고. 바뀐 판은 분석에서 표시하고 바뀐 뒤 구간만 쓴다
6. **봇 반사실의 정책 목록이 결과를 정한다**(#278과 같은 문제) — 목록을 BAL이 판정 전에 고정하고, 목록에 없는 사람의 정책은 사람 데이터로만 본다

## 7. 준비물과 순서

1. `[제안 P-ARCH-44]` 행동 타입 기록(플레이 기록 선택 기능) — 게이트 전, 화면·저장 코드만(출력 불변)
2. 세이브에서 이어 돌리는 봇 실험 모드(`mvp-human.ts` — DUMP의 반대) — 게이트 전, 실험 스크립트만
3. 사후 설문·면담 문항(L2·L3·L5·L6) — PM·각 파트가 문항 초안, 오너 승인
4. 단계 T 완료 → 빌드 고정 → 외부 테스트 → 분석(ARCH가 이 문서 형식으로) → 오너 판정

## 8. 오너 결정 요청

1. 표본(§4): 6~8명, 새 판/7년 차 세이브 반반으로 갈지 — 또는 인원을 늘려 비율을 판정에 쓸지
2. 합격 기준(§5): L1~L6 수치를 이대로 시작점으로 둘지(특히 근거가 얇은 L1 10%·L4 70%)
3. 행동 타입 기록(§3 ①, P-ARCH-44)을 넣을지 — 외부 테스터의 플레이 기록에 행동 종류가 남는다(인자 요약만, 개인 정보 없음)
