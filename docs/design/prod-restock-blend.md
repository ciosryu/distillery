## 1. 지금 코드 사실 `[사실]`
- **보충은 병입 옵션 하나다:** 병입(`bottle`)이나 블렌더 맡기기(`delegateBlend`)에 `restockId`를 넣으면, 새 제품을 만들지 않고 그 제품의 재고에 더한다.
  - 10차 70개월 세이브 확인: 「김포 더 퍼스트」에 몰트 통 48개 · 3 ~ 6년 · 300병을 맡겼더니 재고 83 → 382병, 제품 수 12 → 12였다.
- **병입 칸은 「통 id → L」 하나로 담는다**(`Bottling picked`). 그래서 화면이 이 값을 채워 주면 미리보기 · 경고 · 병입 버튼을 그대로 쓴다.
- **보충이 강제하는 것(`restockChecks`):** 같은 범주 · 병 크기 · 포장 · 도수 · **같은 피니시**. 표기 연수가 내려가면 경고만 하고 막지는 않는다.
- **블렌더 계획 `delegatePlan(s, 목표 육각형, 통들, 병 수)`:** 샘플 기록 육각형(`knownReads`)만으로 목표에 가장 가까운 비율을 찾는다. 순수 함수라 화면이 부를 수 있다. 맛보지 않은 통은 뺀다(#157).
- **`delegated` 표시**는 시장 · 의뢰 목표 채점에만 쓰인다. 보충에는 목표가 없으니, 화면이 계획을 담아 일반 병입으로 내도 결과가 같다.

## 2. (A) 통 계열로 고르기
- **거르개:** 고른 계열의 통만 후보로 둔다.
  - 계열은 병입 탭 「12년 전망」과 같은 분류(`caskFamily` — 버번 · 새 통 / 셰리 / 와인 · 포트)를 쓴다. 필요하면 통 종류(올로로소 · PX …)까지 펼친다.
  - 자동 납품 `caskTypes`와 같은 뜻이다(계열 = 통 종류 묶음).
- **계열 안에서 섞는 법:**
  - 기본 — (B)와 같이 지금 제품 맛에 가장 가깝게 섞는다.
  - 대안 — 자동 납품처럼 어린 통부터 채운다(블렌더 없이).
  - 권장은 앞(가깝게)이다. 이 버튼의 뜻이 「이 계열로 · 이 제품답게」이기 때문이다.
- **주의:** 피니시 제품은 같은 피니시 통만 보충된다(행동이 강제). 그래서 피니시 제품에는 계열 고르기를 숨기고 「피니시 통 그대로」로 둔다.

## 3. (B) 지금 제품의 맛과 가장 비슷하게
- **목표 = 제품의 병입 때 추정 향미 육각형** — 판매 화면 향미 카드가 그리는 그 값이다(F5d #338 ②).
  - 블렌더가 이 목표에 가장 가까운 비율을 `delegatePlan`으로 정한다.
  - 참 향미는 읽지 않는다(I2). 시장 · 평가는 참값으로 보므로, 어림이 빗나갈 수 있다. 블렌딩 테이블과 같은 성질이다.
- **후보는 제품 통 구성 기록(`caskMix` — 공개)의 계열로 좁힌다.** 버번 제품이 육각형만 비슷한 와인 통으로 바뀌지 않게 한다.
- **추정 향미가 없는 제품**(병입 때 샘플 기록이 하나도 없었다): 통 구성 기록의 비율대로 계열별 L을 나눠 어린 통부터 채운다. 그것도 없으면 「먼저 통을 하나 맛보세요」로 멈춘다.
- **블렌디드:** 첫 병입의 몰트 · 그레인 비율(`restockMix` #399 C)을 지킨 뒤, 원액 종류마다 위를 적용한다.

## 4. 늘 지키는 것 — 자동 고르기가 건드리지 않는 통
자동 납품이 쓰는 함수를 그대로 쓴다. 손 보충은 원래 아무 통이나 고를 수 있지만, **자동으로 고를 때는 자동 납품과 같은 약속을 지킨다.**

| 거름 | 함수 · 기준 |
|---|---|
| 보호 태그 · 플래그십 예비(12년 후보) | `autoRestockExcluded` — 표기가 플래그십 숙성(12년) 이상인 제품을 채울 때 · 승리 뒤에만 예비 통을 푼다(#252 · #260 `flagshipGuard`) |
| 연령 띠 정책(10년+ 안 씀 · 5 ~ 9년 6통 남김 등) | `agePolicyFilter` — 판매 탭에서 정한 띠 정책(#380 · #399) |
| 같은 레시피 · 증류 스타일 | `recipeFilter`(#293 · #422) |
| 아는 오염 · 고객 통 · 핸드필 통 | 뺀다(자동 납품과 같다) |
| 표기 연수 | 숙성 최저의 기본값 = 제품 표기 연수. 낮추면 미리보기에 「표기가 n년 → m년」 경고가 이미 뜬다 |

- **담은 뒤 사람이 본다.** 담긴 통 목록에 「◆ 플래그십 예비」 꼬리표 · 띠가 그대로 보이고, 병입은 사람이 누른다.

## 5. 판 도중 최소형 vs 판 뒤 온전한 형

| | 판 도중 최소형 | 판 뒤 온전한 형 |
|---|---|---|
| 무엇 | 보충할 제품을 고른 칸에 조건(숙성 최저 · 상한 · 품질 하한 · (A) 계열 / (B) 맛 유지 · 병 수) + **「자동으로 골라 담기」** → 병입 칸에 통 · L을 채운다 | 조건을 **제품에 기억** → 다음 손 보충이 미리 채우고, **자동 납품도 같은 조건으로 채운다** |
| 코드 | PROD 잎 함수 `restockAutoPick(s, 제품, 조건)` → `{ picked, 뺀 사유 }` + Bottling 묶음 하나 | 필드: (A)는 `autoRestockSource.caskTypes`가 이미 있다 · (B)는 `keepFlavor?: true` 하나 / 규칙: 자동 납품이 (B)면 `delegatePlan`으로 비율을 정한다 |
| 봇 · 세이브 | 그대로 `[사실 — 새 행동 · 필드 없음, 봇은 화면을 안 쓴다]` · PR에서 balance · X0 바이트 대조 | 봇이 쓰지 않으면 그대로. 자동 납품 결과가 바뀌므로 사람형 판에는 영향 · 선택 필드라 마이그레이션 불필요 `[추정]` |
| 크기 `[추정]` | 1 PR(잎 함수 + 화면 + 시험: 거름마다 · I2 · 담은 값 = 병입 미리보기) | 1 ~ 2 PR + 측정(매달 결산에서 최적화 비용 · 블렌더 오차 누적 · 「예상보다」 메모) |
| 리스크 | 화면이 길어진다(보충 칸에 이미 여러 줄) → 접어 둔다 | 자동으로 좋은 통을 몰아 쓰면 S 드묾(#393)이 흔들릴 수 있다 `[측정 필요 — MGT]` |

**반론 · 리스크:**
- **「맛 유지」는 어림이다.** 목표(병입 때 추정)와 비율(샘플 기록)이 모두 추정이라, 마스터 블렌더가 없거나 샘플이 오래되면 빗나간다. 다만 화면이 「어림 · 블렌더 읽기 기준」이라고 밝히면 블렌딩 테이블과 같은 약속이다.
- **(A)와 (B)는 늘 하나만 고른다**(오너 정리). 다만 (A) 안에서도 섞는 법은 (B)와 같게 두기를 권한다. 따로 두면 「셰리 계열」을 고른 순간 맛이 크게 바뀔 수 있다.
- **반론 — 블렌딩 테이블로 충분하지 않나:** 블렌딩 테이블 「내 조건」은 새 제품용이다. 보호 통 · 띠 정책 거름이 없고 「지금 제품 맛」 목표도 없다. 보충에 쓰면 12년 후보를 써 버릴 수 있다.
