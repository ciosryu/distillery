## 1. 왜 템플릿인가

규칙은 결정(#n)으로 하나씩 들어왔다. 결정마다 "무엇을 바꾸나"는 있지만 "플레이어의 선택 → 기회비용 → 상태 변화 → 결과 → 성공 기준"의 고리는 흩어져 있다(audit §3). 템플릿은 그 고리를 한 칸에 모으는 형식이다. **새 규칙을 만들지 않는다** — 기존 결정과 코드를 가리키고, 비어 있는 칸을 드러낸다.

## 4. 작성 규칙

1. **ID:** `REQ-<파트>-<n>`(#279). 파트 = PROD·MKT·MGT·META·ARCH. n은 파트 안에서 1부터, 다시 쓰지 않는다. 임시 결정 ID(`P-…`)·확인 항목(`T-…`)과 따로 센다
2. **위치:** 파트 초안은 `<파트>-stage-t.md` 「요구사항」 절(#279). ARCH는 이 문서 §5와 architecture.md 해당 절
3. **한 REQ = 한 규칙.** 같은 가치를 두 곳에서 다루면(숙성 가치: PROD `agePerception`·MKT 매력도·기대가 — game-program §5) **한 REQ에서 셋 다** 가리키고 주관을 하나로
4. **합격 기준은 인용만.** PROCESS §2(60%)·#264·#263·#277·#278과 오너 결정. 새 수치가 필요하면 `[제안]` — REQ 안에서 정하지 않는다
5. **수식은 코드와 같은 이름으로.** 함수가 바뀌면 10·15칸을 같은 PR에서 고친다
6. **단위·반올림:** 금액은 원 단위 정수, `Math.round`(0.5는 +∞ 쪽 — C#과 다르다, architecture.md §9.4). 표시 반올림과 저장 반올림을 구분
7. **12·13칸은 정보 계약(architecture.md §11)의 등급으로** — 새로 보이는 값이 참값에서 오면 13칸에 새는 길을 적는다
8. **다섯 대안(#280):** 새 시스템(⑤)을 요구하는 REQ는 ①~④로 안 되는 이유를, 기존 개선은 지금 구조가 부족하다는 실증을 18칸에 적는다
9. **설계 검증 질문 8개 — 모든 REQ가 짧게 답한다**(②설계안의 조건). 답은 해당 칸에 쓰고, 칸이 없는 것은 16칸 아래 "검증 질문" 줄에:

| # | 질문 (지시서 §7) | 어디에 답하나 | 답이 "아니오"면 |
|---|---|---|---|
| Q1 | 플레이어에게 **실제 선택권**이 있는가 | 7 | 규칙이면 "선택 없음 + 우회 선택". 선택이 있다고 쓰려면 둘 이상의 합리적 길 |
| Q2 | **A가 유리한 경우와 B가 유리한 경우가 모두** 있는가 | 15 | 한쪽이 늘 낫다 = 단일 지배(#37) — 19칸 실패 조건으로 |
| Q3 | 기회비용이 **수치·상태로** 표현되는가 | 8·12 | 화면이 대가를 말하지 않으면 12칸에 "표시 없음" + G09 연결 |
| Q4 | 플레이어가 **결과의 이유**를 이해할 수 있는가 | 12 | "왜 줄었나"를 알 수 없는 값 — architecture.md §12(G09) |
| Q5 | **같은 시드**에서 재현되는가 | 14·18 | 난수 스트림·명령 순서 계약(architecture.md §9.4·§10.7) 위반 여부 |
| Q6 | **자동화가 전략을 침해하지** 않는가 | 14 | 자동 기능이 플레이어 정책 밖으로 나가는 길(정책 계층 §10 가드) |
| Q7 | 기존 기능과 **중복·상충**이 없는가 | 20 | 같은 값을 두 번 보정 — 주관 하나로 묶는다 |
| Q8 | 이 시스템을 **빼도 결과가 같다면** 존재할 이유가 있는가 | 18(제거 실험) | 결과가 같으면 축소·기각 후보(#280 결론 "축소·기각") — 연출·정보 가치만 남는지 적는다 |

## 9. 템플릿 자체의 엣지 케이스

1. **선택이 없는 규칙**(파산 3개월 규칙) — 7칸에 "선택 없음 + 우회 선택". 비우면 기회비용 분석이 빠진다
2. **세 파트가 같은 값을 다룬다**(숙성 가치) — 한 REQ, 주관 하나(3칸), 나머지는 20칸. 둘로 쓰면 한쪽만 고쳐 이중 보정
3. **합격 기준이 아직 없다**(#264 범위는 잠정) — 19칸 "오너 결정 대기 — 후보: …", 단계 ②. 근거 없는 수치로 ④를 표시하지 않는다
4. **수치만 바뀌는 튜닝** — 단계 T 손잡이 변경은 21칸을 바꾸지 않는다(10칸의 `[튜닝]` 값만). 식 모양이 바뀌면 새 결정(#276)
5. **옛 세이브** — 11칸에 선택 필드가 없을 때의 기본 동작(#187)
6. **Q8 제거 실험이 불가능한 시스템**(판정·진행처럼 빼면 게임이 안 되는 것) — "제거 대상 아님 — 이유" 한 줄. 화면·자동화·보너스 항은 제거 실험 대상이다
