## 2. 확인 점검 — `t-entry-check.sh` 단계

| 단계 | 무엇 | 명령(요지) | 통과 기준 |
|---|---|---|---|
| 1 | 정적 검사 | `typecheck` · `vitest run` · `build` | 모두 성공 |
| 2 | 8입지 스모크 + MVP 생존, **불변식 매달 검사 켬** | `INVARIANTS=1 DIAG=1 balance-sim 2 180 all <8입지>` · `INVARIANTS=1 FARM=1 MVP=micro·standard mvp-survival 4 180` | 모두 끝까지 돈다. 불변식 위반 0, 상태 NaN 0(위반이면 throw로 실패 종료) |
| 3 | 보호가 후보를 지킨다(P7 재실행, #262) | `FLAGSHIP_RESERVE=4·0 P8=1 P7=1 TIER=standard ONLY=X0 AUTORESTOCK=1 mvp-human 5 180` | 끝까지 돈다. **사람이 본다:** 예비 4통의 "144개월 후보"·"플래그십 가능"이 0통보다 많은지(첫 점검: 6.0통·5/5 대 1.6통·4/5) |
| 4 | 3정책 엔진·S6 | `vitest run priceEngine·pricePolicy·autoPriceOrder` | 통과 |
| 5 | 난수 계약 | `rngStreams.test.ts`의 `it.fails(` 수 | 0이면 PASS, 남으면 WARN(구현 전) |
| 6 | 판정 도구 | `P8=1 METRICS=1 TIER=standard ONLY=X0,X5,X12 mvp-human 10 180` | 끝까지 돈다. **사람이 본다:** 기준선 대비 변화(식 v1 뒤에는 새 기준선으로) |
| 7 | 화면 점검 세이브 | `P8=1 TIER=standard ONLY=X0 DUMP=<폴더> mvp-human 1 180` → 59·83·107·119·179개월 | 다섯 파일 |
| 8 | 화면 점검(Playwright) | `vite preview` + `t-entry-ui.cjs` — 세이브마다 불러와 최대 20개월 진행 | 콘솔·페이지 오류 0 · 불러오기 알림(세이브 수리·불변식, #295) 없음 · 판정 화면이 뜬다. 사람 후반 판 세이브는 `HUMAN_SAVE=<파일>` |

- **봇 세이브를 화면에서 이어 하면 봇 행동이 없다**(생산 지시 그대로, 대출·병입 없음). 그래서 이른 세이브(59·83개월)는 파산할 수 있고, 오류가 아니다. 점검 대상은 "화면이 깨지지 않는가"다. 첫 점검(#313)처럼 해금·판정 화면을 끝까지 보려면 현금을 올린 시험 사본을 쓴다.
- **빠른 모드 확인(2026-11-12, `795d5cf`, QUICK=1 — 36개월·1시드):** 1~8단계 PASS, 5단계 WARN(S1~S5 `it.fails` 5개 — PROD·MKT 구현 전). 화면 점검: 107 → 127 · 119 → 139 · 179 → 180 판정 `missed:C` · 59 → 65·83 → 98 파산(봇 행동 없음 — 위 설명). 콘솔 오류 0, 불러오기 알림 0, `priceLog` 기록 있음.
- 스모크 표의 "흑자 전환 평균 NaN개월"은 그 기간에 흑자 전환이 없다는 **표기**다. 상태 값의 NaN이 아니므로 세지 않는다. 상태 NaN은 2단계의 불변식 검사가 잡는다.

## 3. 실행 시간 (대략, 4코어)
- 전체 약 40~60분 `[추정 — 전체 모드는 아직 돌리지 않았다]` — 2단계(입지 8 × 180개월)와 6단계(P8 10시드)가 대부분이다. 빠른 모드는 실측 약 6분.

## 4. 반론·리스크
- 3·6단계는 "끝까지 돈다"만 자동으로 본다. 수치 판단(보호 효과·기준선 변화)은 사람이 본다. 자동 합격선을 두면 단계 T 튜닝 전에 수치를 확정하는 셈이라 두지 않았다.
- 화면 점검은 봇 세이브라 사람 판의 경로(태그를 직접 붙임·정책 바꾸기)를 덮지 않는다. 사람 후반 판 세이브가 있으면 `HUMAN_SAVE`로 함께 돌린다.
