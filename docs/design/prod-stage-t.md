# 단계 T — PROD 확인 목록

> 파트 PROD(생산·숙성·블렌딩·병입) 2026-11-11 작성(오너 "권장안대로" — #260이 ARCH 태그 기반을 기다리는 동안). 단계 P에서 수치 튜닝을 하지 않고 미뤄 둔 PROD 판단을 한곳에 모은다. [mkt-stage-t.md](mkt-stage-t.md)·[mgt-stage-t.md](mgt-stage-t.md)와 같은 꼴이다(#265 — 파트가 측정을 준비하고 BAL이 판정).
> 단계 T 진입 조건(#262, PROCESS §7.2)을 넘으면 이 목록을 「우선」 순서대로 본다. 수치는 모두 `[튜닝]`이다. **판정 기준은 모두 `[제안]`이다** — 오너가 단계 T에 들어갈 때 정한다.
> **판정용 봇은 하나다 (`[결정 #265]`):** 표준 규모 사람형 봇 `mvp-human.ts` P8(MGT)과 `mvp-survival.ts` 4전략. PROD는 손잡이(아래 T-0)만 얹는다.
> **요구사항(Phase B, 2026-11-11):** 맨 아래 「요구사항」 절 — REQ-PROD-1~6(장기 숙성 투자·통별 최적 시점·숙성 가치 단일 출처·샘플링의 가치·크래프팅 인과 경계·확률은 정보에), 실험 명세 A~C, 다른 파트 입력, `[제안 P-PROD-45~47]`.
> **단계 T 진입 조건(#262)의 PROD 몫 — 모두 끝(2026-11-11):** 마지막이던 #252 → 태그 이관(#249 ②)을 했다 — 자동 납품은 숨은 "가장 오래된 4통" 대신 **보호 태그**(플래그십 예비 #260 + 플레이어 "보호")를 쓰지 않고 **"먼저 쓰기"** 태그 통을 먼저 쓴다(`economics.ts autoRestockExcluded`). 예비 통 수는 `PROD_TUNING.flagshipReserve`(4) 하나다(T-PROD-1).

## 항목별

### T-PROD-1 플래그십 예비 통 수 (#259 · #260)
- **근거:** 후반 확인 판(§7.18 1) — 2·3년 표기 제품의 자동 납품이 "어린 통부터" 쓰다가 소비(연 23~33통)가 자동 통입(연 10~20통)을 넘었다. 그러자 플래그십 후보 50통을 모두 썼다. 오너: "몰랐다, 장기 숙성용 캐스크가 모두 소진되어 곤란"
- **보호는 이제 한 곳이다(2026-11-11):** 자동 납품은 태그 "플래그십 예비"(`tags.ts reserveCaskIds`, 통 수 `PROD_TUNING.flagshipReserve` = 4)를 읽는다 — 숨은 #252 집합은 없어졌다. 설계 문서의 기본값(#260 결정 문구)은 **2통**이었고 구현은 #252의 4통을 이어받았다. P7 봇 재현에서는 2통만 지켜도 10/10 판에서 플래그십이 가능했다(W3, 비용 순자산 −0.50억 ≈ 5%). 5통은 2통과 차이가 없었다(W4 대 W5). → 태그가 들어오면 둘 중 하나로 맞춘다. 단계 T 측정 전까지는 4통 그대로 둔다(태그로 옮길 때 숫자를 바꾸면 출력이 바뀐다)
- **손잡이:** `PROD_TUNING.flagshipReserve`(환경 변수 `FLAGSHIP_RESERVE`), 보호 대상(지금: 후보 중 가장 오래된 n통, 고객 소유·오염 확인 통 제외)
- **측정:** P8 X0 대 X3(예비 4통)은 이미 있다(10시드: standard 21.50억 대 21.13억, micro 같음). **다만 P8은 게임의 자동 납품을 쓰지 않고 자기 병입 규칙으로 보호를 흉내 낸다**(`protect` — 가장 오래된 n통은 병입하지 않음). 그래서 게임 규칙(자동 납품 + 예비)을 그대로 재지 못한다 → **MGT에 요청 `[제안]`:** P8에 "위스키 계열은 게임의 자동 납품(#206)을 켜고 보충한다" 선택(`AUTORESTOCK=1`)을 단다. 그러면 `FLAGSHIP_RESERVE=0,2,4,6`을 그대로 돌릴 수 있다
- **볼 것:** 플래그십 가능 판 수(후보 36·72·108·144개월), 자동 납품 "원액 없음" 달 수(#243 알림), 15년 순자산, 플래그십 품질
- **반론:** 예비가 크면 2·3년 표기 제품이 일찍 "원액 없음"이 된다. 그것은 "생산을 늘려라"는 신호라 의도에 맞다(#252 반론) — 다만 신호를 못 읽는 사람에게는 매출 공백으로만 보인다(P-PROD-30과 같은 문제)

### T-PROD-2 생산량 — 표준 규모 후반 공급·몰트 배치 수 (ARCH §7.21 5 · STATUS 「생산량」)
- **근거:** 후반 판 166개월째 순자산 21.14억(목표 24억), 13년 차 → 14년 차에 줄었다. 위스키 판매 8,724병(7년 차) → 762병(14년 차, 10개월). 141~159개월에는 1년 표기 제품도 8번 못 채웠다. 숙성고 150자리 중 최대 75통(50%)만 썼고, 연 생산 LPA는 소규모 4차와 같은 띠(5,200~7,100)였다 — **규모가 커져도 생산을 늘리지 않았다**
- **원인 (2026-11-11 갈림):** ① 행동이다. 오너 답: "늘려봐야 기다리려면 한참 걸려 소용없다(오판)". ② 설비 상한은 원인이 아니다 — 지금 증류기로 월 10배치까지 된다(MGT X12·X13). ③ 자동 통입·④ 수출 수요는 증산하면 따라온다(MKT #277: 수출을 막던 것도 원액 공급)
- **측정 결과와 판단:** 아래 「생산량 판단」. 남은 단계 T 질문은 "숙성고를 채우는 것이 늘 정답인가"다 — 그것이 의도(#137 숙성고 공간 압박)라면 수치는 그대로 두고 **화면으로 알린다**(#272)

### T-PROD-3 생산 건너뛰기 기준 (#267 · #268)
- **근거:** qol.md §3 P6 실험(10시드, 이벤트 끔, **소주까지 멈춘** 실험) — n = 0.5에서 건강한 판 19.80억 그대로, 무너지는 판 파산 102 → 130개월. n ≥ 2는 함정(n = 3이면 4차 판 목표 7/10)
- **다시 잴 것:** 실제 규칙은 **위스키 원액만** 멈추고 소주는 계속 만든다. 그리고 P8은 이벤트를 켠다. 같은 결론인지 본다
- **손잡이:** `PROD_TUNING.whiskySkipFixedMonths`(환경 변수 `WHISKY_SKIP`, 끄려면 `-1e12`)
- **측정:** P8 X0·X2(약한 판)와 `mvp-survival` 4전략에서 `WHISKY_SKIP=-1e12,0.5,1`. 건너뛴 달 수(`MonthReport.whiskySkipped`), 파산 수·시점, 15년 순자산

### T-PROD-4 자동 납품 목표 속도 (#255)
- **근거:** 후반 판 「셰리 블렌드」 재고 1,798병 = 58개월치(§7.18 2). 자동 납품(2개월분)이 판매 꼭대기에서 채웠고, 그 뒤 판매가 꺾였다 `[추정 — 월별 재고 기록 없음]`
- **결정된 방향(#255):** 판매 속도를 max가 아니라 최근 3개월 평균과 수요의 작은 쪽(또는 중앙값)으로. **수치 성격이 있어 단계 T와 같이 본다** — 구현은 P-PROD-40(단계 T 뒤 목록). 순서는 오너가 정한다: T에서 측정만 하고 구현은 뒤로 / 구현을 T 앞에 단계 P 작은 PR로
- **측정 도구:** 아직 없다. MKT `mkt-replay.ts`(세이브 재생)에 자동 납품을 켠 변형을 더하는 쪽이 가장 싸다(MKT T-MKT-3 매몰 원가와 같은 판) — **MKT와 같이**
- **연결:** MKT T-MKT-3(자동 가격이 재고 과잉을 보지 않음)은 이것이 먼저다(PM 의견)

### T-PROD-5 병입비 (#163 · P-PROD-22, 보류)
- **근거:** 오너 보류(2026-11-09) — 단계 P 수치 변경이고, 샌드박스 스모크 파산 합계가 11 → 5로 바뀌는 기준선 변화다. 사람 판에서 병입비는 매출의 10~24%(4차)·11~20%(5차)로 판을 가르지 않았다(§7.15·§7.17)

- **판정 `[제안]`:** 목표 달성 수가 10%p 이상 바뀌지 않으면 #163은 닫는다. 버튼 강조(화면만)는 이미 떼어 낼 수 있게 적어 두었다(§7.15)

### T-PROD-6 어린 위스키 인식 곡선
- **근거:** MVP 첫 위스키는 13~17개월째에 나온다. 1년 위스키는 권장가·매력도가 ×0.77이다. 초반 현금이 이 값에 달려 있다 — MKT T-MKT-11
- **이번에 한 것:** 곡선이 `blending.ts`에 박혀 있어 MKT 실험에서 바꿀 수 없었다(mkt-stage-t.md T-MKT-11 측정 절). → `PROD_TUNING.youngWhiskyFloor`(0.4)·`youngWhiskyCurve`(0.8), 환경 변수 `YOUNG_FLOOR`·`YOUNG_CURVE`로 뺐다(아래 T-0, 기본값에서 출력 불변)
- **판정은 MKT 기준을 따른다.** PROD는 "곡선을 바꾸면 숙성을 기다리는 이유(3년 표기 1.18)가 약해지지 않는가"만 같이 본다 — 기준 `[제안]`: 24개월 인식이 1.0을 넘지 않는다(지금 0.98)

### T-PROD-7 플래그십 S 품질 80
- **근거:** §7.15 3 — 4차 플래그십 「10년」 품질 75.1. S등급 기준은 80(`progress.ts` `GRADE.sFlagshipQuality`, META 소유). 같은 판의 5~6년 제품은 80~82였다. 180개월 안에 12년이 되려면 **36개월 안에 통입한 통**만 쓸 수 있다 → 판 후반의 실력 향상(레시피·직원 레벨)은 플래그십에 못 들어간다. 봇도 S가 0이다(§3 20시드)
- **먼저 물을 것(오너):** "S = 1~3년 차에 좋은 통을 골라 12년 남기는 게임"이 의도인가. 의도라면 기준 80을 두고 "가능한 판이 있는가"만 본다. 의도가 아니면 대안: 기준을 기후별로(한국 75) / 플래그십 숙성을 10년으로(구조 — 단계 P)
- **PROD 측정:** P8 X0에서 플래그십 품질 분포(시드별), 그리고 "3년 차까지 통입한 통 중 품질 상위 2통을 예비로" 바꾼 변형(보호 대상을 오래된 순 → 품질 순). 품질 순 보호는 규칙 변경이라 실험 안에서만 한다

- [사실] **기후는 차이를 만든다.** 대만(TW)은 증발·과숙성으로 3~7년이 최적이다(할인율 0%에서도).
- [사실] **보유의 한계 수익은 대출 금리 수준이다.** 3년 → 6년 보유는 KR·JP 연 4~12%(TW −4~5%), 6년 → 10년은 KR·JP 연 3~7%(TW −6~0%)다. 3년 병입의 내부수익률은 연 60~180%다. 그래서 할인율(자본비용)이 5~8% 근처에서 답이 뒤집힌다 → MGT-C의 정의가 결론을 가른다.
- [사실] **숙성 중반 전의 품질은 10년 품질을 예측하지 못한다.** 120개월 품질과의 순위 상관(스피어만)은 다음과 같다.
  - 36개월 품질: 42개 −0.05, 한국 14개 −0.39
  - 72개월 품질: 42개 +0.84, 한국 +0.57
  - 이유: 첫 통입 통은 3년에 높았다가 떨어지고, 재사용 통은 3년에 낮았다가 10년에 80~88로 오른다
- [사실] **근본 원인은 식의 모양이다.** 권장가와 기대가(MKT `expectedPricePerL`)는 모두 `√(품질/60) × agePerception(연수)` 꼴이다.
  - 품질은 제곱근으로만 들어간다: 72 → 57이면 −11%
  - 연수는 선형 배수다: 3년 1.18 → 12년 2.51, ×2.13
  - 매력도(`appeal`)에도 `agePerception`이 한 번 더 곱해진다
  - 숙성 가치가 **세 곳**(권장가·기대가·매력도)에 들어간다 — audit §6 "이중 보정" 위험이 이미 현실이다

### REQ-PROD-1 장기 숙성은 경제적 투자 선택이다   상태: 초안
- 핵심 재미와의 관계: 시간의 복리(숙성) — "어느 통을 얼마나 오래"가 판단이어야 한다(#273)
- 플레이어의 선택과 기회비용: 통을 묵히면 → 보관비·증발·현금 회수 지연·숙성고 자리를 내준다(그동안 새 원액을 담을 수 없다). 지금 병입하면 → 숙성 프리미엄과 고연수 라인을 포기한다
- 입력·전제: 통별 숙성 상태(참 향미·도수·양), 캐스크 종류·통입 횟수, 숙성고 기후, 판매 수요(국내·수출), 자본비용(MGT-C), 남은 판 기간
- 상태 전이·출력: 틱 3(숙성) — `Cask.contents` 향미·도수·양·`oakMonths`. 병입(행동) — 제품 가격·수요. 바뀌는 상태 없음(요구사항은 결과 분포에 대한 것)

- 플레이어에게 보이는 정보: 숙성 연수(참), 샘플 추정 품질(±σ), 권장가는 병입 미리보기에서만(시나리오) — 참 품질은 보이지 않는다(#143·#167)
- 불변식:
  - ① 전량 장기(모든 통 ≥ 10년)는 어떤 합리적 조건에서도 최선 경로가 아니다
  - ② 같은 조건에서 "일부 장기"가 "전량 3년"을 이기는 조건(생산량·국가·자본비용)과 지는 조건이 모두 있다
- 정상 사례: 6배치 판에서 남는 6년 통을 25% 묵힘 → +2.43억(C672)
- 엣지 케이스·악용:
  - (a) 현금이 없는 초반에 장기 지정 → 파산(B·E) — 화면이 막지는 않되 증산 전망(#272)처럼 현금 회수 시점을 보여야 한다
  - (b) 판 끝이 가까울 때 장기 지정 → 병입 전에 판이 끝나도 순자산은 현물가로 센다(#167) — "판 끝 평가액 노리기"가 병입보다 늘 나으면 안 된다
  - (c) 고금리 급전(20%)으로 숙성 자금을 대는 경우 → 1층에서 모든 통이 3년 최적. 급전으로 장기를 버티는 것이 이득이면 안 된다
  - (d) 숙성고 증설 없이 장기 비율을 올려 새 원액을 못 담는 경우 → 생산이 멈춘다(증산 전망의 "숙성고 여유"와 같은 계산)
  - (e) 대만처럼 과숙성이 빠른 기후에서 장기 → 손해여야 한다(지금 그렇다)
- 측정 지표(audit PROD-A 지정): 통당 누적 비용(생산·보관·샘플), 병입 공헌이익, 연평균 수익률·할인현금흐름, 증발 LPA 감소, 포기한 재투자 기회(같은 기간 3년 라인 병입 감소분), 품질별 최적 병입 연수 분포, 국가·캐스크 민감도, 15년 순자산·파산·목표·등급

### REQ-PROD-3 숙성 가치는 한 곳에서 한 번만 정한다 (이중 보정 금지)   상태: 초안 — MKT와 함께

- [사실] 한 달 생산 자원은 모두 **레시피 사이에 공유**된다(`production.ts runProduction`)

| 자원 | 한도 | 배치당 사용 |

- [사실] **먼저 지시한 레시피가 먼저 차지한다.** 레시피는 생산 지시 목록 순서대로 처리되고, `setOrder`는 새 지시를 목록 끝에 붙인다. 모자라면 뒤 레시피가 "발효조 부족로 n배치 생산 못 함"(결산 메모)이 된다. 화면은 이 순서를 보여 주지 않는다(생산 지시 표는 레시피 순서다)
- [사실] **MVP 시작 설비에서는 발효조가 병목이다**(소규모·표준 같다 — 2,000L 스테인리스 2기, 1,000L 단식 증류기 1기 20회, 디스틸러 30회; 소주 발효 14일·1회 증류, 몰트 발효 4일·2회 증류). 몰트 지시 10배치, 같은 판에서 지시만 바꿔 한 달:

**사실·판단:**
1. [사실] **품질 점수는 향미의 방향을 보지 않는다** — `flavor.ts evaluate`: `38 + 복잡도(축 분포의 엔트로피) + 강도(총량) + 통합감 − 이취 − 자극 − 상한 초과`. 피트 +30.5(육각형이 크게 바뀜)도 품질 +1.3이다
2. [사실] **전형성은 위스키에서 늘 100**이다 — 위스키 범주에는 기준 축(`typicityAxis`)이 없다(증류식 소주 = 누룩·쌀, 백주 = 수수 축이 있고, 진은 주니퍼로 따로 계산). 매력도의 `(0.6 + 0.4 × 전형성)` 항은 위스키에서 죽어 있다
3. [사실] **스타일은 계산되지만 쓰이지 않는다.** 평가는 가장 가까운 스타일(몰트 위스키: 피티드·셰리 캐스크·버번 캐스크 프루티·한국 참나무)과 거리를 내는데, 수요·가격 어디에도 쓰이지 않는다
4. [사실] **향미 방향이 수요에 닿는 길은 트렌드뿐이다**(`blendTable.ts trendFactor`, 일본은 미즈나라 인센스 항 하나 더). 트렌드는 이벤트(`events.ts addTrendShift`)로만 생겨 MVP에서는 이벤트가 열린 60개월 뒤에만 있고, 오고 간다 — 107개월째 피트 +42.9%, 한국 참나무 +23.5%. 59개월째와 트렌드가 없는 달은 "품질만"이다. **레시피·캐스크를 고르는 때(통입)와 파는 때(3년 뒤)가 달라서 향미 선택은 미래 트렌드에 대한 복권**이다
5. [사실] **36개월 기준 경제 효과가 없는 레버(향만 바뀜, 세 상태 공통):** 발효 3일 · 겨울 발효(8°C) · 옹기 발효조(몰트) · 통입 60%(70%는 새 판에서만 +0.7%). **품질 점수로만 이어지는 레버:** 효모 · 발효 7일 · 고온 발효 · 컷 · (트렌드 없을 때) 곡물·캐스크·피니싱. 숙성이 길수록 품질 차이가 줄어든다(피트 12개월 +4.5 → 36개월 +1.3)
6. [사실] **경제적으로 가장 큰 레버는 향미가 아니다:** 증류 횟수(1회면 위스키 범주를 잃는다, 권장가 −77%) · 캐스크 필 수(−11%) · 넓은 컷(−6%) · 병입 도수(+9.7% 권장가) · 국산 몰트(전통주 주세 경감으로 권장가 +32%, 등록 판)
7. [사실] PRD §4.3의 **목재 발효조는 구현되지 않았다**(`FermenterType` = 스테인리스·옹기)
8. [추론] 지금은 "품질 점수 하나를 올리는 레시피"가 정답이고, 향미의 방향은 트렌드 운에 맡긴 장식이다 → game-program §6 엣지 1("고품질 레시피 하나가 모든 세그먼트 장악")과 같다

**스타일 분류 v2 — 플레이어 선택 기준 `[제안]` (MKT f 첫 측정 반영, 2026-11-11)**
- **왜 바꾸나:** MKT가 아래 v1(코사인)을 P8 1시드로 쟀더니 설계 문제 셋이 나왔다
  - ① 총수요 보존 실패: P8 국내 제품은 전부 버번 프루티(fit 0.95)라 KR 수요가 ×1.095로 늘었다
  - ② 숙성 결합: 10년이면 14조합 중 10개가 "한국 참나무"로 분류된다
  - ③ 레버 가림: 피트 레시피를 ex-버번에 첫 통입하면 피티드로 잡히지 않는다(버번 프루티 fit 0.42). 미즈나라는 늘 한국 참나무로 잡힌다
- **정의 (위스키 범주만, 다른 범주는 지금처럼 전형성):** 매력도 배수 = **피트 배수 × 통 배수**
  - 피트 배수 = `1 + p × (w_peat[시장] − 1)`
    - p = 섞은 원액의 피티드 맥아 비중(LPA 가중, 원액 `mashShare.malt_peated`)
  - 통 배수 = `Σ f_k × w_cask[시장][k] + (1 − Σf) × 1`
    - f_k = `Product.caskMix` 계열 비중 — ex-버번 · 올로로소 · 한국 참나무 · **미즈나라**(새 계열)
    - 옹기·탱크 몫은 중립(×1)
  - **w_cask[버번] = 1**: 기본 레시피(언피티드 × ex-버번)가 ×1이 되어 총수요 보존이 기본 레시피에서 자동으로 성립한다
  - 비중을 선형으로 쓰므로 fit 문턱이 필요 없고, 블렌드 비율에 계단이 없다. 피트 레시피를 셰리 통에 넣으면 두 배수를 다 받는다
  - **시장마다 1보다 큰 칸을 하나 이상** 둔다 — 전부 1 이하면 그 시장에서 "안 바꾸는 게 정답"이 된다(엣지 1)
- **근거**
  - 입력이 레시피·통 기록이라 숙성 연수와 무관하다(② 해소)
  - 피트·미즈나라를 직접 센다(③ 해소)
  - 레버 감사 결론(방향 = 선택, 같은 계열 안의 차이 = 품질)과 맞는다
- **대안 B(코사인에서 나무 축을 빼고 미즈나라 스타일 추가)를 권하지 않는 이유**
  - 한국 참나무 목표에 incense 10만 남아 미즈나라와 구별되지 않는다
  - 버번 프루티는 새 원액 축(과일·꽃·곡물)만 남는다. 이 축들은 숙성할수록 옅어져 숙성 결합이 모양만 바꿔 남는다
- **세부**
  - **피니싱:** `caskMix`는 마지막 통 기준이라 피니시하면 그 계열이 100%가 된다. v1은 이대로 둔다(통값·개월을 쓰는 명시적 선택이고, 라벨도 그렇다). 짧은 피니시로 스타일을 싸게 바꿀 수 있으면 `caskHistory` 개월 가중으로 바꾼다
  - **JP 미즈나라:** `incensePremium`(×1.25, 인센스 8 이상)이 이미 있으니 통 가중은 1로 둔다(이중 계산 방지). 한국 참나무가 같은 항을 받는지는 `[확인 필요]`
  - **데이터:**
    - f 측정은 `recipeIds` → 레시피 `mashBill`로 p를 구한다(P8 제품은 레시피가 하나다)
    - 구현 때는 `Product.peatShare?`를 병입 때 `caskMix`(#176)와 같은 자리에 기록한다 — 코어(types·migrate) 작은 PR. 기록 없는 옛 제품은 중립으로 둔다
  - **표시:** `Product.style`(지금 육각형 기준, 쓰이는 곳 없음)을 같은 함수로 바꿔, 화면 표시와 시장 분류가 어긋나지 않게 한다(PROD)
- **반론·리스크**
  - 맛 결과 → 스타일 인과가 약해진다. 피트가 거의 빠진 피트 레시피도 "피티드"로 잡힌다
  - 트렌드는 여전히 육각형 기준(피트 15~25 구간)이라 피트를 두 방식으로 센다 — 트렌드와 곱해질 때 상한을 확인한다
  - 발효 일수 같은 "향만 바뀜" 레버는 이 안으로도 살아나지 않는다. 살아나는 것은 곡물(피트)과 통 종류뿐이다
  - 시장 × 계열 표가 고정이면 시장마다 정답 조합이 생긴다 → 아래 필수 확인 ③

### AP3-PROD-1 자동 가격 3정책(#288)과 PROD — 기준점 · C 정책의 근거 · 불변식 범위 (PM 태스크, 2026-11-11, 기준 `main` `178079f`)

**1. 기준점은 하나 — 기준가(`suggestedPrice`) 대비 배수 (엣지 9)**
- [사실] B1-4 합의로 `suggestedPrice`(PROD 식)는 기준가로 남는다. MKT가 #324에서 정책 수치를 기준가 기준으로 옮겼다: 기본 배수 1.3 · 소진 한 단계 0.1 · 하한 1.04. 옛 "×1.0 · 하한 0.8"은 `h`(×1.3) 위의 값이었다 — PROD가 확인했다(1.0 × 1.3 = 1.3, 0.8 × 1.3 = 1.04)

  - ① 재고 보충 — 품질이 병 수 가중 평균으로, 표기가 가장 어린 값으로 바뀐다(`restockedProduct`, #186)
  - ② 숙성 표기 낮추기 — `autoRestockMinMonths`(#267)로 어린 통을 넣으면 표기가 내려간다
  - ③ 전통주 주세 경감 구간 — 출고량 누적이 구간을 넘거나 해가 바뀌면 `traditionalTaxFactor`가 바뀐다(국산 몰트 판에서 권장가 차이 +32%, G01 표)
  - ④ 지역 세율 상수 — 판 중에는 바뀌지 않는다
- `[제안 P-PROD-53]` **n(`defaultPolicyPrice`)은 정책마다 다르지 않다 — 세 정책의 시작 배수는 같은 n(=1.3)**

  - 정책은 **움직이는 규칙**으로만 다르다 — A는 적체에 한 단계씩 내림(하한 1.04), B는 그달 최적, C는 플레이어가 올린 목표 배수를 분기마다 유지

  - 사건 ③(주세 경감 구간)은 품질 변화가 아닌데 기준가를 크게 움직인다 → C는 그달 바로가 아니라 **다음 분기 경계에서** 다시 맞춘다(12.3 표의 "기준가가 바뀐 달" 규칙을 C에서는 분기로) `[제안 세부]`
  - 대안: 정책별 기본 배수(A 1.3 · B 없음 · C 1.5) — 처음부터 쓸모 있는 값이지만 프리셋으로 읽힐 위험

  - B의 근시안은 B 설계의 결함이기도 하다 → B′를 고치면 C가 이길 자리가 줄어든다. 3정책의 합격 원칙("각 정책이 하나 이상의 조건에서 최선")과 함께 본다
    - MKT 중간 측정(2026-11-11, 10시드 — 판정 아님): B′(팔 수 있는 양 = 재고 + 판매 EMA × 6)가 표준 "프리미엄" 조건과 소규모 정상·과잉 조건에서 1위였다(평균 배수 ×1.5대). PROD 진단과 같은 방향이다 — **근시안을 고친 B′가 C의 경제적 자리를 상당 부분 가져갈 수 있다** → C를 "안정 가격·위험 회피" 성격으로 둘지는 AP3-MKT-1 결론(MKT 문서)과 함께 본다
  - 이 표에서 B가 ×1.0까지 내린 것은 같은 달 국내 진열 전체 공헌을 보기 때문이다(형제 제품 판매 포함). 단일 제품 기준이면 B의 값이 달라질 수 있다
