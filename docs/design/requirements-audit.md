## 2. 우선 조사 8개 — 사실·추론·가설 구분

### 2.1 CES 수요와 SKU 개수에 따른 생존률 차이
- **[사실]** #154: 같은 카테고리 제품 총수요 = (Σxᵢ^ρ)^(1/ρ), ρ = 3. 똑같은 제품 n개면 총수요가 **n^(1/3)배**(2개 1.26배·3개 1.44배)로 **기계적으로 늘어난다**.
- **[사실]** 측정: #137 실험 주종당 1개 8/8 파산·2~3개 0/8(STATUS 확인 항목 24) · MKT `mkt-sku.ts` 2시드 ρ = 3에서 1개 2/2 파산(98개월) · P8 X7(계열당 1제품) 판이 무너진다(#271 보정 기록).
- **[추론]** 지금은 "SKU를 늘린다"가 생존의 사실상 필수 조건이다 → **#275(OWNER-3)와 정면으로 충돌**한다.
- **[가설]** 원인이 ρ 값인지(튜닝), "총시장이 SKU 수로 늘어난다"는 공식 모양인지(구조) 미분리. 같은 생산량·인지도·마케팅·유통에서 재배분 효과와 총수요 증가 효과를 나눠 재야 한다(→ MKT-A).

### 2.2 자동 가격 ON/OFF의 큰 격차
- **[사실]** P8 1차(10시드): X0(자동 가격) 21.50억 대 X5(자동 가격 끔) 8.68억.
- **[사실]** X5는 자동 가격을 끄면 **재고를 보충한 제품의 값을 다시 매기지 않는다**(`mvp-human.ts` `bottleAs` — `autoPrice`일 때만 가격 처리). 첫 병입(어린 위스키 할인 ×0.77·숙성 프리미엄 없음) 값이 끝까지 남는다. MKT가 `mkt-lib.ts`에서 **같은 결함**을 찾아 고쳤을 때 주종당 3개 판이 0.49억 → 19.25억이 됐다(mkt-stage-t.md).
- **[추론]** "자동 가격이 압도적"이라는 결론의 상당 부분은 **수동 가격 정책이 없는 봇의 결함**일 가능성이 높다. 격차의 실제 크기는 모른다.
- **[가설]** 합리적 수동 휴리스틱(예: 병입·보충 때 권장가로, 분기마다 재고 일수로 ±조정)을 넣으면 격차가 크게 준다. 그래도 크면 #200이 지배 전략이다(→ MKT-B).

### 2.3 장기 숙성의 위험조정 기대수익
- **[사실]** #117: 3년 이후 숙성 배수 = 1.18 × (1 + r·연수)/(1 + 3r), 몰트 r = 0.2 → 6년 1.62 · 10년 2.21 · 12년 2.51 · 18년 3.39(상한). **연수만의 일률 함수 — 원액 품질·캐스크·기후와 무관**하다.
- **[사실]** 비용 쪽: 증발(지역별) · 보관비 캐스크당 월 5,000원(#61, 지역 인건비 배수) · 수요는 달마다 쓰지 않으면 사라진다(PRD §6.2.1 기록 — "6년 이상만 병입하는 묵히기 봇은 파산이 줄지만 그래도 어리게 파는 쪽이 이긴다").
- **[사실]** P7: 플래그십 후보 2통 보호 비용 ≈ 순자산 −0.5억(약 5%).
- **[추론]** 프리미엄이 일률적이라 "어느 통을 오래 둘지"의 차등 판단이 약하고, 장기 숙성이 업적(플래그십) 수단에 가깝다 → **#273(OWNER-1)이 지양하라고 한 형태**와 같다.
- **[가설]** 캐스크 품질에 따라 최적 병입 연수가 갈리는지, 샘플링이 그 판단에 값을 더하는지 미측정(→ PROD-A·PROD-B, 자본비용은 MGT-C).

### 2.4 비지터 센터·대출에 몰린 생존 경로
- **[사실]** 3차 판 진단 "비지터 센터가 생존을 갈랐다" · STATUS 확인 항목 3 "소규모에서 비지터 센터 사실상 필수" · MKT `mkt-early.ts` 소규모 2시드: 비지터 센터가 3년 매출의 약 40%.
- **[사실]** 사람 판은 위기 다음 달 정책자금 3억(4차·후반) · 봇은 대출을 최대한 당긴다 · 은행 심사 #65는 닫혀 있다(#210 확인 항목).
- **[추론]** 생존 경로가 "비지터 센터 + 싼 대출"로 좁을 수 있다. 대출이 "필수 조건"인지 "정상 조달 전략"인지 구분하는 측정이 없다.
- **[가설]** 비지터 센터 없는 합리적 운영(소주 비중↑·B2B 제한 매각·설비 지연)도 생존 가능한가(→ MGT-A·MKT-D).

### 2.5 후반 자동화와 의사결정 밀도
- **[사실]** 후반 확인 판: 11년 차 뒤 손이 거의 가지 않았다(13년 차 12개월에 1.3분, mvp.md §7.21) · 자동 기능 6종이 켜져 있었다(자동 통입·자동 샘플·자동 가격·자동 납품 등).
- **[추론]** 자동화가 반복 작업뿐 아니라 판단(가격 목적·재고 배분)까지 대신하고 있다.
- **[가설]** 후반 경험은 #274(OWNER-2) 게이트에서 본다. 단계 T 진입 조건에는 넣지 않는다.

### 2.6 참 품질 은닉과 평가액을 통한 간접 누수
- **[사실]** 시나리오 판에서 통별 견적은 추정 품질 ±1σ 범위로만 보인다(`B2B.tsx` `caskQuote`) · #143 블렌딩 테이블 누수는 샘플 기록 방식으로 막았다 · #167 순자산 원액 항은 참 품질(근거: 새는 것은 합계뿐, 현물 지수 ±3%).
- **[사실]** #167 반론에 이미 "초반 통 1~2개면 합계 ≈ 그 통"이 적혀 있다.
- **[가설]** 초반·한 통 단위 행동(통입·판매) 전후 순자산 차분으로 참 품질을 역산할 수 있는지, IB 제안가·자동 기능 결과로 새는지 미점검. **누수가 확인되기 전에는 버그로 단정하지 않는다**(→ ARCH-C).

### 2.7 120개월 측정과 180개월 판정의 구분
- **[사실]** `npm run balance -- <시드> <개월> <전략> <지역> [입지]` — `120`은 **개월 수(10년)**이고 **샌드박스**(`newGame`, 시나리오 판정 없음)를 돈다(`scripts/balance-sim.ts` 15~20행).
- **[사실]** MVP 판정은 `mvp-survival.ts`·`mvp-human.ts`(P8) 기본 **180개월**, 시나리오 목표 판정(#145·#263).
- **[사실]** PROCESS §2 단계 T 완료 기준은 "8개 입지 × 40시드에서 모든 입지 최다 1위 전략 60% 이하, 파산률·난이도 목표 충족" — 샌드박스 도구에 맞춰 쓰였다(#153, MVP 이전). #264 목표 달성률 범위는 **MVP 180개월** 기준이다.
- **[추론]** T 완료 기준이 두 실험 가족(샌드박스 120개월 · MVP 180개월) 중 무엇을 말하는지 문서끼리 어긋난다. **명세 공백(확인됨)** → 오너 결정 E2.

### 2.8 봇 전략의 대표성과 40시드 판정의 타당성
- **[사실]** P8은 사람 판 하나(후반 확인 판, standard)에 맞춰 보정했다 · 변형에 따라 결론이 크게 흔들린다: 수출 증분 1차 ≈ 0 → 2차 +2.46억 · 몰트 4 → 6배치 19.80억·목표 2/10 → 38.06억·10/10(#276·#281).
- **[사실]** P8은 게임의 자동 납품을 쓰지 않는다(PROD 요청 `AUTORESTOCK=1`, #279) — #252·#267 규칙이 판정 봇에서 돌지 않는다.
- **[사실]** #264 "잘 하는 봇 = 4전략 + P8 중 최선"인데, X12·X13 같은 변형이 "P8"에 드는지 정해지지 않았다.
- **[추론]** 지금 봇 하나로 #264를 판정하면 정의에 따라 결과가 정반대가 된다. 판정 전에 "합리적 전략 집합"을 정해야 한다 → 오너 결정 E3.

## 7. 오너 결정 요청 (OWNER-1~3 재질문 없음, 중요도순)

### E1. 진단 결과 "구조 변경"이 필요할 때의 처리 시점 (최우선)
OWNER-1~3 진단(PROD-A·MKT-A·MKT-B)에서 공식 모양 변경(예: #117 품질 연동, #154 총시장 고정, #200 정책형)이 필요하다고 나오면, 단계 T는 구조 변경을 하지 않으므로(PROCESS §2) 시점을 정해야 한다.
- **A.** 건마다 오너가 승인하면 **T 진입 전**에 처리 — #262 진입 조건에 그 항목을 오너 결정으로 추가. 기대효과: T 튜닝이 한 번에 끝난다. 리스크: T 진입이 늦어진다.
- **B.** T에 들어간 뒤 발견되면 P로 되돌린다(PROCESS §2 "거꾸로 가기"). 기대효과: T 진입이 빠르다. 리스크: 40시드 판정을 다시 돌린다.
- **C.** G 이전 게이트로 미룬다. 리스크: OWNER-3 위반 상태(1 SKU 파산)로 T 판정을 한다.
- 기존 규칙과의 충돌: A는 #262를 넓힌다(오너만 가능).
- **PM 권고: A.** 진단은 지금(P) #262 작업과 병행하고, 구조 변경 여부는 진단 결과를 보고 건별로 결정한다.

### E2. 단계 T 완료 기준이 가리키는 실험
- **A.** 둘 다 — ① MVP 시나리오 180개월(P8 + `mvp-survival` 4전략) 40시드: #264 목표 달성률·#263 등급·파산 ② 샌드박스 8입지 120개월 40시드: 지배 전략 60%·파산률. 기대효과: 출시 범위(MVP)와 전체 게임(샌드박스) 모두 본다. 리스크: BAL 일이 두 배.
- **B.** MVP 180개월만 — 샌드박스는 깨짐 방지 수준.
- **C.** 지금 문구 그대로(샌드박스 120개월) — #264와 따로 논다.
- 기존 규칙과의 충돌: PROCESS §2 T 완료 기준 문구 변경(오너만 가능).
- **PM 권고: A.** 각 기준에 "판정 보류 구간"(PM-2)을 붙인다.

### E3. #264 "잘 하는 봇"의 범위
P8 변형(X12 6배치·X13 8배치 등)을 "잘 하는 봇"에 넣으면 standard는 너무 쉽고(10/10), 빼면 너무 어렵다(2/10).
- **A.** 사람 재현 P8 X0만. 리스크: 사람의 오판(증산 안 함)이 난이도 기준이 된다.
- **B.** 합리적 변형 중 최선. 리스크: 봇이 비용을 덜 느끼면(대출 무한) 너무 쉽게 판정.
- **C.** 둘 다 보고: "최선 합리 전략" 달성률로 #264 범위를 판정하고, P8 X0(사람형)은 입문 보호 지표(#264 보조 조건 a)로 쓴다. "합리적 변형" 목록은 BAL이 판정 전에 고정한다.
- **PM 권고: C.** 증산 전망 화면(#271·#272)이 들어가면 사람형도 증산할 것이므로, 사람형만으로 기준을 잡으면 화면 효과를 못 본다.

### E4. 요구사항 문서 체계 (낮음 — PM 제안 승인)
- REQ ID `REQ-<파트>-<n>`(임시 ID `P-…`·확인 항목 `T-…`와 겹치지 않게). 파트 REQ 초안은 각 `<파트>-stage-t.md` 「요구사항」 절 → Phase D에 PRD 해당 절로 승격. 공통 템플릿·색인은 `docs/design/requirements.md`, 밸런스 명세는 `docs/design/balance-spec.md`, 게이트는 `docs/design/late-game-gate.md`.
- **PM 권고:** 이대로. PRD v1.7 승격은 Phase D에서 변경 묶음이 확정된 뒤 제안한다.

## 10. BALANCE-SPEC 제안 (PM-2의 범위)

- **위치:** `docs/design/balance-spec.md` (정본). 파트 `*-stage-t.md`는 항목별 측정 도구·손잡이, balance-spec은 **공통 실험 단위·지표·판정 절차**만 — 같은 내용을 두 곳에 쓰지 않는다.
- **담을 것:** ① 실험 단위(국가·입지·티어·기간·시드 목록·봇 정책/버전·초기 조건·바꾼 변수·관측 지표) ② 실험 가족 구분 — 샌드박스(`balance-sim`, 기본 120개월, 판정 없음)와 MVP(`mvp-survival`·P8, 180개월, 시나리오 판정) ③ 공통 지표 정의(파산률·목표 달성률·B/A/S 비율·최종 순자산·월 영업 현금흐름·최고 차입·현금 부족 개월·12년↑ 원액/병입 성과·전략별 수익·변동성·SKU 수별·가격 정책별) ④ 실험 설계 규칙(같은 시드·한 번에 한 변수·40시드 표본 오차·판정 보류 구간·행동 모델 결함과 공식 실패의 구분·커밋/봇 버전/시드 기록) ⑤ 기존 기준 연결(PROCESS 60%·#264·#263) — **합격선은 새로 정하지 않고 기존 기준과 오너 결정만 쓴다**.
- **선행:** E2·E3 결정, MGT-D 지표 정의.
