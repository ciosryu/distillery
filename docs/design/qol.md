## 2. 측정 — 캐스크 2,500개 (오너 답변 8 "먼저 성능 측정부터")

`npx tsx scripts/experiments/perf-casks.ts <세이브> [출력 폴더]` — 봇 179개월 세이브(원액 든 통 83)의 통을 복제해 늘렸다. Node, 중앙값.

| 통 수 | 상태 복사 | 행동 1회 | 월 진행 1회 | 저장 JSON | 직렬화 | 필터(10년 이상 몰트) |
|---|---|---|---|---|---|---|
| 100 | 5.1ms | 4.5ms | 16ms | 0.58MB | 3.4ms | 0.01ms |
| 500 | 9.1ms | 8.4ms | 30ms | 1.02MB | 7.5ms | 0.02ms |

| 2,500 | 30.1ms | 29.8ms | 68ms | 3.25MB | 20.7ms | 0.06ms |

화면(Playwright, 2,500통 기록 파일, 빌드 미리보기): 불러오기 0.25초 · [1개월 진행] 0.31초 · 저장 성공(3.25MB) · 숙성 중인 캐스크 칸 열기 0.08초 · **"나머지 더 보기"로 2,500줄 펼치기 4.2초 · 펼친 채 행동 1회 1.7초** · 콘솔 오류 0.

**결론:**
- **시뮬레이션은 병목이 아니다.** 행동 1회 30ms(통째 복사 `structuredClone`)·월 진행 68ms. 일괄 행동을 한 번의 dispatch로 묶으면 복사도 한 번이라 충분하다. 필터 인덱스는 필요 없다(0.06ms)
- **병목은 목록 렌더링이다.** 화면 51곳이 `useGame((g) => g.state)`로 상태 전체를 구독해, 무엇이 바뀌어도 펼친 2,500줄을 다시 그린다(1.7초). → ① 목록은 **필터로 고른 통만** 보이고 한 번에 그리는 줄을 제한한다(지금 "30통 + 더 보기"를 페이지·가상 스크롤로) ② 캐스크 줄은 `React.memo` + 줄 단위 구독 ③ 일괄 선택은 줄을 하나씩 누르는 대신 **조건(태그·나이·종류)으로** 고른다
- **저장 크기를 지켜본다.** 2,500통에 3.25MB다. 브라우저 `localStorage`는 보통 약 5MB다 — 30년 샌드박스(제품 이력·보고서가 더 쌓인다)에서는 넘을 수 있다 `[추측]`. 4MB를 넘으면 경고하고, 넘을 것 같으면 IndexedDB를 검토한다(Godot 이식에는 해당 없음)

## 3. 생산 건너뛰기 — "현금이 n개월 고정비 아래면 그 달 생산을 건너뛰고 알림" (오너 답변 2)

`P6=1 npx tsx scripts/experiments/mvp-human.ts 10 180` — 그 달 월초 현금 < n × 매달 나가는 돈이면 생산 지시를 0으로. 10시드 × 15년 · 이벤트 끔.

| n | 4차 재현 판 (15년 순자산 · 목표) | 비지터 센터 없음 (순자산 · 파산) | 3차 행동 셋 (파산 월 중앙) |
|---|---|---|---|
| 0 (규칙 없음) | 19.80억 · 10/10 | 8.19억 · 1/10 | 10/10 (102월) |
| **0.5** | **19.80억 · 10/10** | **8.17억 · 1/10** | **10/10 (130월)** |
| 1 | 19.79억 · 10/10 | 7.87억 · 1/10 | 10/10 (130월) |
| 2 | 19.14억 · 10/10 | 5.79억 · 1/10 | 10/10 (107월) |
| 3 | 16.98억 · **7/10** · 파산 1/10 | 1.93억 · **파산 4/10** | 10/10 (106월) |

- **n = 0.5개월(고정비 보름치)을 쓴다.** 건강한 판·약한 판에서 손해가 없고(19.80억 그대로), 무너지는 판에서 파산을 28개월 늦춘다
- **n ≥ 2는 함정이다** — 2차 판(생산을 멈춰 3~5년 차 위스키를 잃음)과 같은 방향으로, n = 3이면 4차 판도 목표 7/10·약한 판 파산 4/10. 그래서 규칙은 "정말 바닥일 때 한 달 쉬기"에 그친다
- 알림: 건너뛴 다음 턴 **화면 맨 위에 크게**(파산 경고 자리와 같은 급) — "이번 달 위스키 원액 생산을 건너뛰었다 — 현금 x < 고정비 보름치 y. 위스키는 n년 뒤 그만큼 빈다. 대출·급전으로 현금을 만들면 다음 달 다시 만든다" + [대출·급전 받기]. 생산 지시는 바꾸지 않는다(다음 달 현금이 돌아오면 저절로 다시 만든다 — 5차의 "다시 켜는 걸 잊었다"가 생기지 않게)
- **범위 (`[결정 #249]` 오너 답 ③):** 이 규칙은 **위스키 원액(몰트·그레인)만** 멈춘다. 소주는 계속 만든다. 소주 생산 건너뛰기는 **별도 버튼**으로 둔다. 위 표는 소주까지 모두 멈춘 실험 값이다 — 위스키만 멈추는 규칙으로 다시 잰다
- 소유: 규칙은 `production.ts`(PROD), 알림은 코어 UI(ARCH). 봇 출력이 바뀔 수 있다(이 실험의 봇도 n = 0.5에서 4차 판은 같았다) — PM이 비교
- **구현 `[제안 P-PROD-42]` (PROD, 2026-11-11):** `production.ts` `whiskySkipCheck` — 시나리오 판에서 생산 단계(틱 2) 시작 때 현금 < `WHISKY_SKIP_FIXED_MONTHS`(0.5) × `monthlyFixedCost`이면 그 달 **몰트·그레인 주문만** 건너뛴다(소주·진은 그대로, 생산 지시는 안 바꿈). 보고서에 `whiskySkipped {cash, threshold}`와 메모를 남긴다 — **맨 위 큰 알림(파산 경고 자리)은 ARCH 몫으로 이 필드를 읽으면 된다.** 소주는 생산 지시 칸의 **[이번 달 소주 생산 건너뛰기]** 버튼(그 달 한 번만, `production.skipSojuMonth`). 지시 칸에 "이번 진행 때 위스키 원액은 쉰다" 줄. 샌드박스는 그대로
  - 측정(위스키만 멈추는 규칙, main 대비): 밸런스 8입지·MVP 생존(micro·standard 10시드) **바이트 동일**(봇 현금이 보름치 밑으로 안 간다). 사람형 봇 `mvp-human 10 180`: E(몰트 감산) 15년 순자산 3.29 → 3.27억, F(대출 안 씀) 최저 현금 −0.24억(33월) → −0.17억(32월), 파산 판정 그대로 — 나머지 줄 같음

## 4. 스마트 인벤토리 설계

**상태 (모두 선택 필드 — #187, 스키마 v15 그대로)**
- `inventory.tagDefs?: { id: string; label: string; color: string; effect?: TagEffect }[]` — 태그 정의는 한 곳. 이름·색을 바꾸면 모든 원액에 반영
- `SpiritLot.tagIds?: string[]` — **태그는 원액에 붙는다**(오너 답변 7). 통입하면 통의 원액으로, 원액 빼기(#205)로 탱크에 가면 탱크 원액으로 따라간다. 통이 비면 태그도 사라진다(통은 다음 원액을 깨끗하게 받는다). 탱크 합치기(#166)는 태그를 합집합으로, 여러 원액을 섞어 병입하면 제품에는 남지 않는다
- `TagEffect` (오너 답변 4 — 태그에 규칙 효과): `protect`(보호 — 자동 납품·자동 통입 원액 선택·블렌더 맡기기 자동 선택·IB 입찰 대상에서 빠지고, 수동으로 쓸 때는 #240 확인에 "보호 태그" 경고) · `prefer`(먼저 쓰기 — 자동 납품·맡기기가 이 원액을 먼저 고른다) · 없음(표시만)

**선택기 (sim 순수 함수 — 테스트·Godot 이식 가능)**
- `selectCasks(s, q: { tagIds?, minAgeM?, maxAgeM?, kind?, warehouseId?, tier?, hasContents?, excludeOwner?, excludeProtected? }) → caskId[]`

**일괄 행동 (오너 답변 5·6)**
- 새 행동은 둘만: `tagCasks { caskIds, add?, remove? }` · `moveCasks { caskIds, warehouseId, tier }`(비용: 통당 소액 인건비 `[튜닝]` 기본 2만 원 — 단계 T). 나머지(통입·병입·샘플·맡기기)는 이미 id 배열을 받는다
- **모든 일괄 행동 앞에 순수 `plan*` 함수**: `planMove(s, ids, target) → { ok: id[], skipped: { id, reason }[], cost }`(자리 모자람·고객 소유·핸드필 지정·오염 등). 화면은 `skipped`가 있으면 **창을 띄운다**: "n통은 처리할 수 없다(이유별 목록) — [가능한 통만 처리] [모두 취소]". 자리가 모자라면 같은 창: "자리 m칸이 모자라다 — [가능한 만큼 옮기기] [취소]"
- 행동은 `ok`만 받고 다시 검사한다 — 행동 안에서 하나라도 실패하면 아무것도 바꾸지 않는다(한 번의 dispatch = 한 번의 복사 = #240 확인 한 번)
- 화면 부품: 코어 `kit.tsx`에 `BulkPlanDialog`(창) · 캐스크 목록은 필터 바(태그·나이·종류·위치) + 고른 수 + 일괄 버튼 줄

## 5. 마스터 디스틸러 SOP (오너 답변 1)

오너 답변 1은 세 가지다: (a) 디스틸러 편차를 더 크게 (b) 성공한 배치 결과를 고정 재현 (c) 레시피를 골라 쓰게 관리. **(a)와 (b)는 그대로 두면 부딪힌다**(편차를 키우면 재현이 안 된다) → 둘을 잇는 안:

- **레시피 북 = 레시피 + 기준 배치.** 배치가 잘 나오면 [기준 배치로 저장] — 그 배치의 실측(품질·수율·육각형)을 레시피에 붙인다(`Recipe.reference?`)
- **SOP 숙련도.** 같은 레시피를 같은 증류기로 돌린 횟수가 쌓이면 편차가 기준 배치 쪽으로 줄어든다. 새 레시피·고친 레시피는 편차가 크다(a). 오래 돌린 SOP는 기준 배치를 거의 재현한다(b). 편차 σ = 기본 σ × (1 − 디스틸러 b/150) × 1/√(1 + 같은 SOP 배치 수/12) `[튜닝]`
- 난수는 **새 스트림** `rngFor(seed, month, 'production:sop')` — 다른 단계 결과가 바뀌지 않는다(코드 원칙). 원재료 값·날씨·발효 온도는 지금처럼 들어간다 — "고정 재현"은 레시피·운전 쪽 편차만 줄인다
- **레시피 버전(c):** 생산 지시에 쓰인 레시피를 고치면 새 버전("○○ v2")으로 저장하고, 지시는 고른 버전을 계속 쓴다. 레시피 북 화면에서 버전·기준 배치·숙련도를 보고 골라 지시에 넣는다
- 소유: 규칙(`production.ts`·`Recipe`)은 PROD + 코어 필드, 화면(레시피 북)은 PROD
